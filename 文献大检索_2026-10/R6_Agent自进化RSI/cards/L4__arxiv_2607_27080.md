# MemSecBench: Tracking Agent Memory Poisoning from Persistence to Consequence and Repair (2026, arXiv 2607.27080)

## 问题与动机
记忆系统让 agent 跨会话保留复用信息，但也让恶意内容持久化：一次交互中写入的恶意指令可能很久后被召回并悄悄塑造真实动作（例：供应商 onboarding PDF 里的临时付款指令被存成永久规则，因丢失时间元数据，7 月 13 日把款打到废弃账户）。现有评测只覆盖生命周期片段，缺一个把同一恶意语义从写入→验证的外部后果→选择性修复全程追踪、并在固定 agent/模型/环境下配对比较记忆后端的受控基准。

## 方法拆解
- **基准构成**：310 个链接式生命周期案例，来自 48 个真实场景（代码与科学/日常生活/办公），每案例是任务包 T=(ρ, x_W, x_E, x_F, ℓ)：干净初始记忆源 ρ + Write/Execute/Forget 三阶段 agent 任务 + 评估器专用标签（四设计轴：失败模式/风险/载体/记忆类型 + 7 个 checkpoint rubric + E3 后果契约）。案例由 GPT-5.5 经 6 步 skill-guided 人工把关流程构建（静态门校验+查重+人工准入）。
- **评测协议**：Write–Execute–Forget 生命周期，隔离容器运行。7 个 checkpoint：W1（确定性写检查）/W2（恶意语义持久化）；E1 召回暴露/E2 采纳/E3 案例定义的外部化后果（Execute 成功=E1∧E2∧E3）；F1 目标恶意语义移除或中和/F2 所有必需良性记忆语义保留。Execute 与 Forget 从同一验证过的中毒后状态 M_W 的独立副本出发。判定基于 checkpoint 专属证据包（evidence pack）：W1 确定性，其余由外部 judge（DeepSeek-V4-Pro）按 rubric 只引用可采证据，程序化门校验证据可采性/时序/完整性——agent 自述、意图、无证据的工具调用不算数。
- **指标**：MPSR（写入持久化率）、MESR（中毒成功者中的链路完成率）、E2E-ASR（全链路攻击成功率）、SRSR（选择性修复成功率=移除恶意∧保留良性）。
- **实验矩阵**：2 agent harness（OpenClaw/Hermes）× 4 记忆后端（Native/Mem0/Mem0-Graph/A-MEM）× 3 LLM（DeepSeek-V4-Pro/MiniMax-M3/GPT-5.5）= 24 配置。

## 数据与实验
全 24 配置：MPSR 宏均 84.2%、E2E-ASR 50.3%、SRSR 56.1%（条件于中毒成功）。Finding 1：E1 召回 76.1% 仅微降，E2 采纳 76.1%→53.7% 是最大收缩——**采纳是存储恶意语义与有害行为间的决定性边界**。Finding 2：F1 通过 86.3% vs F2 仅 62.5%，SRSR 56.1%——**良性记忆保留是修复的主要瓶颈**（删了恶意但伤及良性的附带损伤是主要失败源，只报"目标移除率"会高估修复质量）。Finding 3：抗性与可恢复性是不同维度——OpenClaw/DeepSeek 下 A-MEM 把 E2E-ASR 59.0%→56.5% 但 SRSR 46.3%→87.6%；Mem0-Graph 反向。Finding 4：无统一更安全的后端，效应随配置反转。Judge 与人工一致性 90.60%/91.80%（500 条分层样本）。

## 创新点
1. 首个把同一恶意语义从写入→验证外部后果→选择性修复全链路追踪的记忆安全基准（对照表显示此前无工作同时覆盖 IW/DC/ST/SR/MMI 五维）；2. 选择性修复定义 F1∧F2（恶意移除+良性全保留），揭示"修复的附带损伤"这一被忽视的失败模式；3. 证据包+程序化门的证据制判定协议；4. 24 配置受控配对比较。

## 局限
每配置-案例只跑一次（描述性统计，无方差）；恶意语义为文本注入，未覆盖多模态记忆（视频/图像记忆中毒）；修复是被动的单轮 Forget 提示，不评估任何主动修复算法；文本域（code/science/daily/office），无具身或长视频场景。

## 与本选题关系

overlap：核心概念"选择性修复"（F1 移除错误/恶意语义 + F2 保留良性记忆）与我们的"记忆错误定位+局部修复"高度同构——它证明了"修复时不许伤及无关记忆"是公认难点（SRSR 仅 56.1%，附带损伤为主因）；其 7-checkpoint 证据制判定可借鉴为我们修复验证协议的参照。
difference_from_ours：对象是安全攻击（对抗性写入）而非自然发生的记忆错误；任务是评测而非提出修复方法；无多模态/视频记忆，无错误定位自动化。引用价值：为"局部修复必须保良性记忆"提供量化动机（F1 86.3% vs F2 62.5% 的差距），并提示我们的修复闭环评测应含 preservation 指标。
