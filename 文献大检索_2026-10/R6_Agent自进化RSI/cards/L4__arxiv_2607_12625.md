# KnowAct-GUIClaw: Know Deeply, Act Perfectly, Personal GUI Assistant with Self-Evolving Memory and Skill (2026, arXiv 2607.12625)

## 问题与动机
OpenClaw 类个人助手框架两大瓶颈：跨平台 GUI 交互能力不足、无内建自进化机制。直接把独立 GUI agent 塞进 host 框架有四个缺陷：跨 app 指令的中间数据在自由文本摘要中丢失、GUI 观测天然部分可观测、成功/失败轨迹用完即弃（重跑同类任务从零探索）、多数 GUI 工作流不利用非视觉捷径（deeplink/intent/web 工具）且捷径未经页面验证不能安全固化为技能。主张"Know Deeply, Act Perfectly"：积累的人机交互与任务执行经验直接提升执行精度与效率。

## 方法拆解
- **agent 架构**：Know–Route–Act–Reflect 四段循环，host（Qwen3.5-397B/Kimi-K2.6）+轻量 GUI executor（Qwen3.5-35B-A3B）双层。host 拥有会话上下文/工作区记忆/用户画像/工具编排，决定 what；executor 拥有截屏感知/动作规范化/设备后端/技能校验/轨迹记录，决定 how。GUI 任务接口返回结构化输出（完成状态/摘要/终态屏幕），未完成任务成为可恢复 checkpoint。
- **记忆读写机制**：经验记忆（受 ReasoningBank 启发）——轨迹格式化为 action-and-UI 摘要，成功/失败分离 prompt 各诱导至多几条可操作记忆项；跳过短/异常轨迹，每任务封顶条数、同 app 去近重。记忆分 advisory（语义检索）与 policy（直接注入）两种使用方式。跨 app 数据流用类型化 blackboard：子任务 (g,h,I,O) 元组契约，只读声明输入、只写声明输出，缺失即 fail-closed 防伪造。
- **进化或修复闭环**：Reflect 阶段蒸馏轨迹——**技能修复优先于新抽取**：检测到复用技能失败时，记录失败步/屏幕证据/错误/原技能/历史反馈，用 evolution prompt 原位更新该技能（可缩描述、加守卫式可选障碍处理、刷新过期目标与状态契约），禁止换成无关工作流或加破坏性终止动作；无失败复用技能时才挖掘新技能。技能带可靠性计数器与逐步状态契约（deterministic state contract 或视觉 valid-state check），不匹配时有界恢复子目标/跳过障碍步/回退普通执行。Shortcut 从 manifest 挖掘仅为候选，验证 run（前台 app/ADB/UI 树/截图→verifier 判可用性/页面状态/载荷保持）通过才提升为一步技能。
- **训练方式**：无权重训练，冻结模型+外置记忆/技能库进化。

## 数据与实验
MobileWorld GUI-Only 117 任务（pass@1）：Kimi-K2.6 配置 61.5（host+memory）→64.1（+skills），超 Seed-2.0-Pro 63.2、GPT-5.5 62.4 等闭源模型；Qwen 侧：35B 裸 executor 24.8 → +host&mem 34.5 → +skills 37.9 → 用 Kimi 蒸馏的记忆+技能 41.0（跨模型迁移 +16.2 点，对 Kimi 配置迁移 +8.5%）；397B host 直接干部分子任务达 46.2（token 成本最低 260,516/任务，host total 仅 10,982）。技能复用任务子集（83/87 个）：GUI 步数 -3.3，token 约 -6%，SR +4.9/+1.9。AndroidDaily（iOS 设备，194 resolved）：总 78.61 vs UI-TARS-1.5 56.64，Analyze 类 77.08 vs 36.71。

## 创新点
1. 修复优先于新抽取的技能原位进化机制（带失败证据的定向 skill repair，而非重建）；2. 类型化 blackboard 信息契约防跨 app 数据伪造（fail-closed）；3. 状态契约校验的混合动作空间（GUI/skill/deeplink/ask）与 shortcut 页面验证提升管道；4. 证明冻结模型下外置记忆+技能可跨模型家族迁移（Kimi→Qwen +16.2 点）。

## 局限
自进化限于技能与文本经验层，无记忆错误定位机制（失败教训按轨迹级写入，不验证既有记忆项对错）；技能修复依赖轨迹级失败信号+VLM 判断，无系统性归因；AndroidDaily 依赖 LLM judge+人工评分且 41 任务 unavailable 计 0 分争议；评测主体为单一 run（pass@1），未报告多种子方差。
