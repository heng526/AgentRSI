# RegenHarness: A Robot Agent Harness with Evidence-Gated Recursive Self-Improvement (2026, arXiv 2609.27612)

## 问题与动机
长程机器人执行需要区分三种东西：模型提议、控制器终止、验证过的任务完成。随任务长度增长，链式成功概率 ∏pᵢ 下降，系统必须检测失败转移、保留中间状态、选择回退、防止早期假阳性完成污染下游。核心系统问题：**(i) 谁有权更改可信任务状态；(ii) 什么证据可流向规划器/技能/验证器/恢复策略；(iii) 已接受进度与恢复开销如何从持久、身份与版本绑定记录中重建**。定位为 HROS 机器人操作系统的 agent harness 升级。

## 方法拆解
- **架构**：模型循环（推理级提议生成）与 agent 循环（选择-执行-验证-提交-有界恢复的任务级过程）分离。版本化技能调用绑定显式前置条件/目标效果/资源需求/证据要求/取消语义/恢复策略；capability card 统一 VLA/导航/TAMP/世界模型/传统控制器异构后端，路由按可检视评分 s(π)=w_p·p̂−w_r·r̂−w_u·û−w_l·l̂−w_c·ĉ−w_h·ĥ（ĥ 为历史失败/转移残差惩罚）。
- **记忆读写机制**：版本化记忆区分 O_k（观察事实，来源与新鲜度已知但任务含义未验证）与 C_k（经验证路径接纳的提交事实）；五角色记忆（working/spatial/episodic/operational/semantic），长期记录要求 provenance/置信度/有效区间/验证状态；更新以 supersedes/conflict 关系追加而非静默覆盖（event sourcing，有序事件重建任务进度）。技能不能直接写 C_{k+1}，只能产出证据包 Z_k=(I,k_ctx,O_before,O_after,P,Δ̂_k) 与提议更新。
- **验证-提交门**：判定词表 {satisfied, violated, ambiguous, stale, unsafe}；仅 satisfied 且 task/node/invocation/state-version 身份匹配才推进提交事实；controller done ⇏ node success ⇏ goal success（三层停止条件分离）；缺证据 fail-closed，歧义触发主动重感知。四个角色隔离上下文 C1 规划/C2 技能/C3 验证/C4 恢复——验证器不继承规划器的完成声明（防自证）。
- **进化或修复闭环（evidence-gated RSI）**：改进对象是 harness 配置（上下文选择规则/任务模板/路由偏好/有界恢复策略），不改模型权重、不许削弱提交门与安全联锁。执行记录→修订生成器产出带 change manifest（受影响组件/动机 trace/预期效果/回滚版本）的候选→固定回归集 R_j（含 stale-evidence/重复请求/中断运行/资源冲突案例）验证→接受谓词 A（保安全与证据契约+指定检查无回归+预定目标指标改进+发布授权）→任务边界版本化发布/回滚，活动任务钉在原配置。
- **预算化恢复**：结构化失败类→有序升级阶梯（target_not_found: 重感知→调视角；no_progress: 局部重规划→换技能；unsafe: 安全停→人类交接），每动作消耗显式恢复预算；无新证据重复同一失败动作被确定性禁止。
- **训练方式**：无在线权重更新。

## 数据与实验
真实四足机器人部署（办公室/入口环境，ROS 2/MCAP 记录）：语音触发仓库巡检全流程（语音会话记录/任务 ID/图像校验和/导航回执跨阶段链接）；VLM+omni_planner 探索与建图；两条导航线路（17.62 m 往返与 18.83 m 起终点重合环路）论证"完成取决于执行历史而非端点接近"。6.8 节给出 harness 执行与 RSI 配置更新的评估判据（明确验收标准而非模型自评）。**无大规模量化对比实验**——以部署案例+协议定义为主。

## 创新点
1. 首个面向具身机器人的证据门控 RSI 协议（跨任务配置修订+固定回归检查+发布授权+版本回滚+不许削弱自身验收谓词）；2. O/C 双事实集与身份-版本绑定提交门（证据包式记忆写入）；3. 角色隔离上下文（验证器不继承规划器声明）抑制自证完成；4. 结构化失败类驱动的预算化恢复阶梯。

## 局限
以系统论文+案例部署为主，RSI 协议未做量化评测（无修复前后对比数字、无基准对比）；单机器人单主机；验证依赖证据质量（共享传感器/模型误差需独立裁决，作者自认）；路由评分非学习所得。

## 与本选题关系
撞车风险：**低-中**（具身机器人域，但"证据门控"概念与我们核心术语高度重合）。
overlap：其"证据包 Z_k→verifier 判定词表→身份/版本绑定 commit gate"是我们"证据驱动记忆写入/修复验证"在物理域的严格版；supersedes/conflict 追加式记忆更新=记忆修复不覆盖历史；其 RSI 不许削弱验收谓词的原则适用于我们修复策略进化。
difference_from_ours：域是机器人任务状态而非多模态记忆内容；RSI 只有协议定义无量化验证；无跨任务策略进化（改进的是配置规则）。引用价值：(a) "verdict 词表+satisfied 才提交"可作为我们记忆修复提交门的设计参照；(b) 其真实部署使"证据门控"概念在具身域成立，我们在视频记忆域做对应物时需引用以划清增量。
