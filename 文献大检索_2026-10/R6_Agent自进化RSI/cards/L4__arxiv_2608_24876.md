# Recursive Experiential–Working Memory Evolution for Long-Horizon Agent Harnesses / Recuris (2026, arXiv 2608.24876)

**注：本篇即池内已有解读笔记的 Recuris，本卡为该 canonical_paper_id 的批次内重读，结论与已有笔记对照一致。**

## 问题与动机
长程任务中 RSI 困难：交互史增长遮蔽任务状态、技能调用错位——现有经验记忆方法从初始指令或全量历史检索，执行展开后两者都不可靠（指令过时/历史混杂已完成步骤、未决目标、执行噪声）。核心缺失不是经验不足而是**紧凑可靠的任务状态**。另一痛点：现有方法主要从最终成败学习，"知道错了但不知修哪"——技能库、任务状态、调用机制、验证器都可能是病灶，导致记忆更新粗粒度、弱定向。

## 方法拆解
- **架构**：冻结 LLM + agent harness 中的可进化记忆控制层 M_k=(E_k 技能记忆（agent-skill 格式）, W_k 工作记忆规范（状态 schema+更新提议）, ρ_k 调用策略（deliverer 家族：触发谓词+检索键）, C_k checker 集合)。外层改进程序固定，递归只发生在记忆控制层。
- **任务内闭环（verified EM–WM coupling）**：结构化工作状态 w_t（每 goal 记 content/status pending-done-blocked/证据/blocker）；state-grounded skill invocation——在定义好的执行事件（如起草状态变更工具调用时，合成 not-executed 结果拦截）按 w_t 检索技能；evidence-grounded state update——WM 规范提议下一状态、checker 集对照观察 o_t 裁决、固定 kernel 只提交被证据支持的状态变更。
- **跨任务进化闭环（错误定位→局部修复→验证门）**：结构化 trace Γ_k=(x_k,{w_t,E_t,a_t,o_t,w̃_t+1,c_t,w_t+1},y_k) 记录每步状态/技能/动作/观察/checker 决策；固定 Meta-Agent 从 Γ 把每个诊断出的失败归因到四个记忆组件之一，**只修补被归因的组件**（其余原样复制，scoping 按 edit 强制）；补丁经固定验证门——须修复源任务且不回归 held-out 开发集，否则记忆保持不变（bounded recursive loop）。
- **训练方式**：无参数训练，基座模型保持厂商原样。

## 数据与实验
4 个长程基准（τ²-Bench Retail/Telecom、SkillFlow、Terminal-Bench 2.1）× 10 模型（3B 开源到 frontier）：37 个完成的 model-benchmark 对中 35 个提升。τ²-Retail：GPT-5.6 Sol 58.3→76.1（+17.8）、Claude Opus 5 72.4→87.9（+15.6，超该基准无 Recuris 时任何模型最佳 9.7 点）；SkillFlow：Qwen3.6-27B 42.2→58.7（+16.6）、35B 35.3→48.8（+13.5）。优势随时程增长而扩大（最长任务 +32.2 点），常见长程失败模式最多降 80%。**错误定位实验（核心证据）**：向四组件之注入已知故障，固定 judge 从三种证据条件归因——仅结果 13.0%（低于 33.3% 常数底线）、原始轨迹 37.0%、结构化 trace Γ 64.8%（macro precision 27.6%→64.4%）；invocation 故障是"非事件"，无 Γ 时 0%/有 Γ 38.9%。消融：去掉 checker 在 τ²-Retail 上通过率变化为 0（该域 checker 不 bind）。进化记忆跨任务、跨模型可迁移；两种 Meta-Agent 实现收敛；gated 更新保住既有能力。

## 创新点
1. EM–WM 耦合把执行变成**结构化诊断证据**——记忆系统的每次行为都被记录，使组件级失败定位成为可能（64.8% vs 13.0% 是本批最强的定位量化证据）；2. 组件级 scoped patching（每个 edit 绑定一个被归因的失败）；3. 验证门控的 bounded 递归（修复源任务∧held-out 不回归才准入）；4. call-time 拦截式技能注入（合成 not-executed 结果）。

## 局限
技能/文本域（工具调用对话、终端），无多模态感知；"记忆内容"是技能与状态 schema，不是事实型多模态记忆条目；checker 需要域内可验证信号（作者自认 checker 不 bind 的域无法测该组件）；定位 judge 仍有 ~35% 错误率且 skill-content 类故障提升最小；评估 judge/LLM 依赖单一固定实现。
