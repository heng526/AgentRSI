# ModularRSI: Modular and Generalizable Recursive Harness Self-Improvement (2026, arXiv 2609.14857)

## 问题与动机
Harness RSI 要可泛化仍难，三个耦合挑战：(1) **数据层**——现有方法常直接在评测基准或其子集上演化 harness，无法区分可复用改进与 benchmark 专适配；(2) **轨迹层歧义**——单条/单边轨迹把系统性 harness 缺陷与任务特定推理/解法细节纠缠，直接优化产生迁移差的任务特定修改；(3) **机制级 credit assignment**——即使识别出反复出现的行为缺陷，也难定位到单体 harness 中该负责的组件；整 harness 优化纠缠无关机制、修改难归因难验证。

## 方法拆解
- **架构（五模块分解）**：把可演化 harness（初始为 Harbor 的 Terminus-2）按行为机制分为 Agent Loop（推理-行动-观察流程/恢复行为）、Tool Use、Observation Management（过滤压缩环境反馈）、Context Management（历史保留/压缩/检索）、Task Completion Detection 五个功能模块，各自限制修改范围、独立并行演化、互不共享中间更新。
- **对比轨迹分析（错误定位机制）**：每任务 rollout K 次按奖励分 Positive（全成功→找冗余低效机会）/Contrastive（有成有败→**同任务成败轨迹配对对比**找功能级差异因素）/Negative（全败→先查 Trajectory Memory 历史成功轨迹配对，否则单边诊断循环/工具误用/无效恢复/过早终止）三组。跨任务聚合诊断为 JSON 结构化 findings（模块/证据/理由/提议）。修改目标选择按支持任务数投票排序，抑制实例特异失败影响；每函数维护 Evolution History 防重复/振荡修改。
- **验证门（三重）**：Program Check（AST/import/协议合规/发现契约/静态自省，失败即 diff 回滚）→Diff Review（LLM 审查修改是否编码任务特定解法/启发式，过特异即拒绝回滚）→Execution Validation（随机抽 2 任务实际执行验证，运行时错误即回滚）。
- **跨模块整合**：五模块独立演化后统一集成并在演化集上再跑一轮，识别/消除重复机制与冲突；之后函数库冻结。函数库管理：Function Merge 去冗余+Task-Aware Function Composer 按任务激活子集。
- **协议**：benchmark-disjoint——2,000 个独立策划的可执行演化任务（外部来源构建，实例级相似度过滤+人工审查），下游评测前冻结 harness。

## 数据与实验
TerminalBench 2.0（89 任务）+ SWE-Bench-Verified（500 任务），DeepSeek-V4-Flash-Preview 骨干，3 epochs、每域 120 演化任务。域内：TB2.0 47.57→52.43、SWE-V 73.40→76.45；跨域迁移：TB 演化的 harness 提 SWE-V 到 75.80、SWE 演化的提 TB2.0 到 49.40；TB2.0 Pass³ 30.34→35.96（执行可靠性提升）。跨模型：冻结的 TB 演化 harness 在 GLM-5.2 59.55→61.80、MiniMax-2.5 41.57→44.94、DeepSeek-V4-Flash 47.57→52.43 均提升。模块化消融（关键）：Non-modular 46.44、Joint all-module 44.19 均低于基线 47.57，ModularRSI 52.43——限制修改范围是增益来源；单模块各自 +1.9~+3.0（Agent Loop 单模块最高 50.56；Observation Management 把步数 34.70 压到 22.50），集成后 52.43 超加性。与现有 RSI 方法对比中声称唯一同时满足模块化+全 harness 演化+不用基准数据（Table 1 对照 AutoHarness/Meta-Harness/AHE/Self-Harness/RHO/HarnessFix/Living-Harness/HarnessForge/HarnessBank/RSEA/TACO）。

## 创新点
1. 同任务成败轨迹对比作为 harness 级错误定位信号（把粗粒度任务成败转译为功能级修改信号）；2. 五模块受限修改域+独立演化+集成消冲突，实证"限制修改范围"本身是增益来源（joint/non-modular 反而掉分）；3. benchmark-disjoint 演化协议+2,000 任务公共资源，把"泛化 vs 过拟合评测"变成可检验命题；4. 三重验证门+diff 过特异性审查+回滚。

## 局限
文本终端/代码域，无多模态；轨迹分析由 LLM 完成、无严格因果归因验证；演化集每域仅 120 任务、3 epochs（规模与轮数有限）；Pass@3 指标与单 run 报告；五模块分解是人工先验划分。

## 与本选题关系
撞车风险：**中高**（harness 层 RSI 的方法论最完整版本之一；与 Recuris/AutoMem 同族）。
overlap：五模块分解与受限修改域≈我们的"记忆子系统模块化+局部修复"；同任务成败对比+跨任务聚合定位≈我们的"证据驱动错误定位"；三重验证门+diff 过特异性审查≈我们修复准入的防过拟合机制；跨模型迁移与冻结基座设定一致；benchmark-disjoint 协议对我们评测设计是直接模板。
difference_from_ours：修复对象是 harness 代码/执行机制而非**记忆内容**（没有"这条记忆是错的"的概念）；文本域无多模态证据链；对比信号是 rollout 成败而非多模态证据一致性。与 AutoMem 的区分：AutoMem 搜离散模块菜单，ModularRSI 直接改 harness 代码函数。写作时需将三者（Recuris/AutoMem/ModularRSI）作为"文本域记忆/harness 修复闭环已建立"的证据群，我们的增量钉在多模态记忆内容级修复。
