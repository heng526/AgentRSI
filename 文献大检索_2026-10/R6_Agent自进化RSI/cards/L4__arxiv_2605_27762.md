# PEAM: Parametric Embodied Agent Memory through Contrastive Internalization of Experience in Minecraft (2026, arXiv 2605.27762 v2, Northwestern/NEU/华南理工/HKBU/BNU-HKBU)

## 问题与动机
- 具身 agent 记忆几乎全是非参数式：轨迹/反思/技能外置存储、推理时重新注入 prompt——每次召回消耗上下文预算、检索与 prompt 构造增加决策延迟、经验始终外置。作者称之为"缺失的固化通路"（consolidation pathway）：外置记忆支持召回，但未说明被选经验如何成为参数化能力。
- 理论依据：CLS 互补学习系统（快 episodic 库+慢参数库经离线固化耦合）；DeepSeek-V4 的"先培养领域专家再蒸馏合并"是同型模式。

## 方法拆解
- **Agent 架构（两层）**：慢层=慎思 LLM（开放推理、课程提议、代码合成、结果验证）；快层=多模态 Mixture-of-Experts LoRA（骨干 Qwen3-VL-8B-Instruct），按语义技能类别 {craft, gather, combat} 物理隔离的适配器 {θ_c}，反射式执行已固化技能。推理先走快路径（路由→适配器生成代码→验证器核查），失败或无适配器回退慢层，成功/修正轨迹写入情景库 E。
- **记忆读写/固化机制**：
  - How：情景库含成功轨迹流 D_succ 与失败-修正对 D_cpair={(x,τ_f,τ_c,c)}（四阶段构造：失败识别→修正匹配→上下文匹配→质量门）；只更新对应类别适配器，L=L_BC(成功轨迹 next-token NLL)+λ·L_DPO(轨迹级偏好损失，τ_c 为 chosen、τ_f 为 rejected，π_ref=本轮固化前冻结检查点)，λ=1.0。BC 项是承重项：DPO 不提供动作解析器所需的格式级似然信号。
  - What：参数化值得度 PV(s)=w1·U_cost（EMA 未来调用频率×代码长度，检索成本节省）+w2·U_stab（成功率）−w3·P_redun（冗余）−w4·R_forget（干扰/遗忘风险）。
  - When：自触发固化 STC——基于 agent 自身失败统计的无量纲触发（Z(s)>z_α 且 PV top-q），跨任务分布免调参迁移。
- **进化闭环**：探索失败→修正→（PV+STC 双门）→轨迹级 DPO 写入隔离适配器→快路径免检索执行→验证失败再回退慢层。抗遗忘靠架构性参数隔离而非正则化。
- **训练方式**：适配器训练（LoRA/DoRA，cosine+5% warmup）；骨干与慢层 LLM 冻结。

## 数据与实验
- Minecraft 1.19 + VOYAGER 框架（Mineflayer、code-as-action），held-out 长程任务套件 11 任务×33 试次，3 seeds。
- 主结果：PEAM 69.7%（23/33，Wilson 95% CI [0.530,0.834]）vs VOYAGER 54.5%（18/33），+15.2pp（McNemar p=0.018）；中位单次调用延迟 5.5s→3.2s（−42%）；每任务 token ~31,200→~4,600（−85%）。对最强检索基线 B2 Optimus-1-rep.（多模态上下文强化检索）再 +9.1pp，token 28.4K vs 4.6K。
- 遗忘序列实验：per-category 隔离遗忘 0%；单共享 LoRA 32.4%；EWC 43.3%；naive full-FT 78.5%。
- 消融：去 BC 丧失可部署格式；PV vs 启发式选择、STC vs 固定调度（少 37% 固化周期达到同等性能）、视觉检索权重扫描等。
- 方法论发现：forward-pass 偏好边际无法预测 generate 路径可部署性；量化端侧服务引入特有失败模式（merge_adapter 于量化权重、parser-token 预算失配）；轨迹重切片可作跨分布触发评测的受控替代。

## 创新点
1. 把"失败-修正对"作为一等训练信号，用轨迹级 DPO 把修正行为（而非文本反思）内化为参数技能——错误修复的参数化路线。
2. 固化决策形式化：what（PV 四维评分）×when（无任务阈值的自触发）双门。
3. 遗忘抵抗来自每类适配器物理隔离（结构性而非正则性），遗忘实验直接验证。

## 局限
- 技能类别为固定三类手工集合 {craft,gather,combat}，类别分配发生在验证期——新域需重新定义类别集合；PV 权重 w1-w4 手工设定。
- 只在 Minecraft/VOYAGER 框架验证，作者明示机器人操作/web agent 迁移超出范围；任务规模小（33 试次）。
- 修正对质量依赖环境侧验证器可判定成败；开放任务无 oracle 时管线失效。
- DPO 固化是"把成功修法写进参数"，不含对已固化错误技能的定位与回滚（固化了坏技能如何发现并撤销未讨论）。

## 与本选题关系
- **撞车风险：中**。
- **overlap**：①同为 Minecraft/Optimus-1/VOYAGER 谱系（池内已有 Optimus-1 笔记，本文直接以 Optimus-1-rep 为基线）；②"失败-修正对"四阶段构造管线（失败识别→修正匹配→上下文匹配→质量门）与"证据驱动错误定位→局部修复"在数据构造层面同构，且明确"把修复本身固化为能力"；③双门（what/when）的固化治理与我们"哪些错误值得修、何时修"的调度问题一致。
- **difference_from_ours**：PEAM 的"修复"是参数级技能内化（训练适配器），我们坚持冻结基座+外置视频记忆的修复算子；PEAM 无错误定位环节（修正对靠验证器成败标签天然可得，不做多步归因）；无视频记忆（状态为文本代码+截图流水，非 M3-Agent 类长视频记忆架构）；其跨任务维度止于类别隔离与触发迁移，不沉淀可审计的策略库。引用定位：PEAM 证明"修复经验值得内化"，我们回答"在不动参数的前提下如何定位与修复视频记忆中的错误并跨任务沉淀策略"。
