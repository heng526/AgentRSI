# MemLineage: Lineage-Guided Enforcement for LLM Agent Memory (2026, arXiv 2605.14421, 中科院信工所)

## 问题与动机
- 持久记忆已成 agent 的攻击面：AgentPoison（触发绑定后门）、MINJA（查询时注入）、MemoryGraft（跨会话经验投毒）、Zombie Agents（休眠Payload）构成两阶段威胁——恶意内容经正常写入路径入库、未来会话再以指令形式复活。
- 最难案例"LLM 介导洗白"：不可信内容被检索进上下文后，agent 自己生成衍生摘要并以自身主体身份提交——签名层完全无法与良性摘要区分；多会话后该洗白条目被无关查询召回并触发敏感动作。
- 现有防御四大缺口：签名层只验作者身份不追溯衍生来源；IFC 规划器（Fides）标签不跨 LLM 推导步持久；检索层过滤（RAGPart/RAGMask）分不清良性摘要与洗白载荷；粗粒度记忆门控牺牲有用衍生记忆。

## 方法拆解
- **立场**：把记忆防御当作"监管链（chain-of-custody）"问题而非过滤问题。六模块：
  - M1 溯源元数据（三级源分类 Trusted/Semi-trusted/External，导出 Derived-Trusted/Derived-Untrusted 标签）；
  - M2 密码绑定（逐条 Ed25519 签名 + RFC-6962 Merkle log 锚定）；
  - M3 append-only 日志；
  - M4 血统 DAG+加权传播——边记录"哪些被检索条目影响了新记忆"（归因算法三种：uniform-weight、防注入加固的二级 LLM 判官 LM-self-eval、white-box attention）；max-of-strong-edges 传播规则保证 Untrusted-Path Persistence 定理（任一全程强边的外部祖先路径强制链尾继承 untrusted 标签）；
  - M5 verifier-aware 检索；
  - M6 敏感动作门+权威修复（tool 参数对照逐工具权威规则；当可信溯源提供合法替换值时可做"保效用修复"——authority repair）。
- **训练方式**：无训练；LLM 判官用 JSON-envelope 结构防提示注入；集成 LangGraph 中间件。

## 数据与实验
- 确定性 mechanism-isolation harness（钉死攻击者行为、无真实 LLM 调用），3 攻击族×3 防御格：no_defense 全失守；sig_only 关闭 AgentPoison 列但在 MemoryGraft-style 与 sleeper-via-derivation 失守；**MemLineage 三列 ASR 全部降为 0**。
- τ×K 消融（退化判官调度 w0=0.9, d=0.7）：最深边权 w_K=0.9·0.7^(K-1) 为约束；允许 K=5 派生跳数需 τ≤0.10，而非 K=1 测量暗示的 τ≤0.30。
- 开销：热路径逐操作亚毫秒级（Ed25519 逐条签名主导），远低于任何 LLM 调用噪声底。
- Codex-backed AgentDojo 桥：脆弱 tool-output 配置下 no-defence 与 sig-only 在全部 6 个 banking 对上失败（6/6），所有 MemLineage 行 strict ASR 0/6；含 authority-repair POC、vulnerable-agent 压力测试、自适应洗白边界讨论。核心工件 CI 字节级验证。

## 创新点
1. 记忆洗白（sleeper-via-derivation）威胁的形式化与可复现 workload，把"派生条目 authenticity≠trustworthiness"立为记忆安全的分离性测试。
2. 密码学溯源+LLM 介导血统 DAG 的组合，max-of-strong-edges 传播规则带形式化定理——记忆条目"证据来源链"的可验证追踪机制。
3. authority repair：基于可信溯源的参数级替换修复（保效用的局部修复雏形）。

## 局限（作者自述）
- **"Prevention is not recovery"**——MemLineage 只阻止 untrusted 血统justify敏感动作，不提供对已污染记忆的检测、清洗或恢复机制（仅 authority-repair POC 覆盖参数替换）；被投毒的记忆仍留在库中并污染检索。
- 白盒 attention 归因需开源权重；最强归因依赖 LLM 推理可信假设；单主机部署；adaptive 对手评测留作 future work。
- 纯文本记忆；无任务效用侧的错误概念（只论信任标签，不判断记忆内容正确性）。

## 与本选题关系
- **撞车风险：低-中（问题不同但机制相邻）**。
- **overlap**：其血统 DAG+归因算法（"哪些检索条目影响了新记忆"的加权边）正是"证据驱动错误定位"所需的基础设施——错误记忆的溯源问题与污染记忆的溯源问题同构；其 authority repair 是"局部修复"的一种（参数替换）；"错误写入端产生、后续会话放大"的威胁叙事与我们记忆错误的传播叙事一致。
- **difference_from_ours**：MemLineage 防的是对抗性投毒（信任标签），不判断记忆内容的任务正确性（一个从错误但"trusted"来源派生的错误记忆它不管）；无任务反馈驱动的错误发现（它没有"任务失败→定位→修复"闭环）；"Prevention is not recovery"一句可直接引用为"记忆修复是 open problem"的证据。我们的差异点：任务证据驱动（非安全标签驱动）+面向视频多模态记忆+修复后可跨任务沉淀策略。
