# ScienceBuddy: Recursive-in-Recursive Self-Improvement for Interactive Scientific Agents (2026, arXiv 2609.17523)

## 问题与动机
科研协作中对话内纠正答案≠跨任务改进。核心问题：科研 agent 如何把与研究者的协作转化为工作程序与底层能力的持续改进？现有反思/harness 优化改指令与程序、rubric-RL 改模型，但"协作本身"如何供给协调重复程序学习与策略学习的任务与评估标准，未被系统回答。发布 ScienceBuddy：交互式科研工作区+continual learning。

## 方法拆解
- **架构**：224 工具/22 功能模块（基因组学/分子与癌症生物学/药理学/生物成像/文献检索/数据库）+Python/R/Bash 执行+持久工作区；ReAct 循环+Trajectory 视图；模块化基础设施与可插拔 harness 分离——指令、技能、上下文管理程序是 harness 的可编辑组件，工具/执行基础设施/rubric/评估器固定。
- **学习信号**：协作记录→自包含任务+任务特定 rubric（ConstructRubric 从完整协作轨迹构造，冲突需求先消解；历史答案与研究者认可**不自动当科学真值**）；打包为 Harbor 任务（instruction.md/task.toml/environment/tests），同一任务支撑 SFT（rubric 合格轨迹拒绝采样）与 RL（on-policy rollout+rubric 奖励）。
- **内递归（冻结模型的 harness 进化）**：任务模型 θ_k 固定；独立固定辅助模型（GPT-6 Astra）做证据接地的轨迹诊断（引用相关动作/观察、映射到候选程序编辑）；每次提议只做**有界编辑**（增/删/改一个 scoped skill、改一条指令、或改一个上下文设置，其余组件不动），schema 检查强制编辑范围与大小预算；父/候选在相同开发任务/种子/预算下配对评估，接受规则 Valid∧Δ>0（平局留父；评估含既往成功任务防回归）；被拒编辑与分数变化留在优化器历史。
- **外递归（冻结 harness 的模型 RL）**：harness 演化使旧难题变平凡→按当前模型+harness 校准环境难度并增广（变科学输入/分析条件/延长计算步依赖）；task-adaptive rubric 奖励（加权和，可执行检查优先+固定 judge 判科学解释）驱动 GRPO；训练期 harness 与 rubric 固定；历史交互只供任务定义与诊断证据、不当 on-policy 训练样本。
- **双向耦合**：harness 修订塑造训练轨迹与难度，模型更新改变继承程序的有效性；更新后模型-harness 对重新评估并部署，研究者交互开启下一循环；全部 harness/环境版本保留。

## 数据与实验
案例研究（LAB-Bench/Biomni-Eval 四任务家族：文献阅读/数据库判断/协议排障/基因与变异评估）。三轮 RinR 循环（Qwen3.5-4B，每轮 10 步 harness 进化+20 次 RL 更新）：harness 验证准确率逐轮 38.9%→44.4%、34.4%→46.7%、61.1%→70.0%；RL 期训练奖励各轮前后半 33.3%→38.8%、44.1%→60.5%、57.8%→69.8%；held-out 单次测试准确率 42.2%→73.3%，33.3% 测试题由错转对、2.2% 由对转错，四任务家族全升。固定模型 harness 适应与固定 harness 模型学习分别给出独立案例。

## 创新点
1. "recursive-in-recursive"嵌套范式：内层冻结模型改 harness、外层冻结 harness 训模型，双向耦合（harness 塑造训练经验、模型更新反过来开启新 harness 适应机会）；2. 协作记录→任务+rubric 的自动化管道（研究者反馈作标准不作真值标签）；3. 有界单点 harness 编辑+配对验证接受（含防回归）与递归细化；4. 环境难度随 harness 演化重新校准（防止 harness 进化"掏空"RL 训练信号）。

## 局限
案例研究规模小（测试集 90 题/42.2%→73.3% 为单次实验）；Qwen3.5-4B 小模型+科学域特定；rubric 由 LLM 构造存在标准漂移风险；改权重外环与我们冻结基座设定不符（但其内递归冻结模型部分与我们一致）；无多模态视频记忆。

## 与本选题关系
撞车风险：**中**。
overlap：其"内递归"（冻结模型、有界 scoped 编辑、配对开发集验证、防回归、被拒历史保留）与我们修复闭环的验收协议几乎一致；双向耦合提示我们：记忆修复与（若有的）策略进化也应互相校准——修复后错误率下降会改变后续进化的目标分布；"环境难度重校准"对应我们"修复后错误分布重估计"。
difference_from_ours：对象是科研文本/代码工作流的 harness 程序+模型权重，不是多模态记忆内容；无视频记忆错误概念。引用价值：作为"嵌套 RSI"（harness×model 双层）的先例，支撑我们"内容修复层×策略进化层"双层闭环的设计合法性；其协作→rubric 管道提示我们修复验证标准也可从用户/证据交互中自动构造。
