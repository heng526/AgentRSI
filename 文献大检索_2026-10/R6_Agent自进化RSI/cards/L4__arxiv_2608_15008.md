# Harness the Memory: A Holistic Evaluation of Memory Substrates in Memory Agents (2026, arXiv 2608.15008)

## 问题与动机
记忆 substrate（记忆的底层表示/存储介质）选择缺乏受控证据：52 个近期记忆增强系统的 landscape 分析显示三大缺陷——62% 的基准-系统对集中在 LoCoMo+LongMemEval 两个对话数据集；全部报准确率但只有 21% 报任何效率指标、管理成本与压缩比无报道；81% 只用 GPT 家族骨干，无法把 substrate 效应与模型特异行为分离。要造通用自适应记忆系统（按 query/任务/部署约束路由 substrate），必须先知道每种 substrate 在什么 operating regime 下 preferable——这要求把 substrate 作为唯一受控变量的 harness 评测。

## 方法拆解
- **评测设计**：11 个记忆方法（M1–M11）横跨 7 个 substrate 家族（外部：Flat Index M1 dense/M2 sparse、Text Record M3 Gist、Structural M4 Evolving Notes/M5 Dual-Level Graph、Hierarchical M6 树、Refinement M7 蒸馏策略/M8 Skill Bundles；内部：Weight M9 adapter 微调、Activation M10 full context/M11 episode-clustered re-prefill），统一 harness/骨干/prompt/辅助 LLM（gpt-4o-mini），26 个指标（12 性能+14 效率：写/读/管理 token、调用、延迟、存储等）。
- **基准**：用户中心（LoCoMo 1986 题、MemoryAgentBench 四能力 AR/LRU/TTL/CR，AR 即 LongMemEval-S）+ agent 中心（ALFWorld 134 unseen 任务、BigCodeBench-Hard 148 代码任务）。三个骨干：Qwen3-8B、Qwen3-32B-AWQ、Gemma-4-26B-A4B-IT。Zep/Mem0/MemGPT 因辅助 LLM 预算不可比放入附录分析。
- **消融**：检索深度扫描（LoCoMo k∈{1,2,5,10,20}；ALFWorld k∈{1..5}）+ 注意力探针；MAB CR 上三档上下文压力（6K/32K/262K tokens）测扩展性。
- **训练方式**：M9 之外的 substrate 均不改权重（M9 是被评的内部方法之一）。

## 数据与实验
核心发现（定性+代表性数字）：(1) **最优 substrate 随 regime 反转**：结构图（M5 dual-level graph）在对话 QA 领先（如 Qwen3-8B LoCoMo P4 0.648 最高）但在 agent 任务被 Pareto 支配；refinement（M8 skill bundles）在具身规划领先但 QA 落后；M5 成本可达 M2 的 10–100 倍。(2) **检索广度跨 regime 反转**：QA 中检索越多越好；agent 任务中检索过深有害——注意力探针显示检索深度增大时注意力从任务上下文转向检索块（QA 中答案恰在检索块、agent 任务中策略需关注当前观察）。(3) **扩展性**：262K tokens 下 refinement 家族质量-延迟俱佳（M8 延迟 ~1s→~10s，存储固定大小）；结构家族（M4/M5）graph 重建成本随输入暴涨；M10 full-context 质量 0.27→0.47 但读代价线性；M9 权重微调无时间选择性更新机制，CR 停在 0.18–0.22。设计法则：**trade read breadth for write depth**；结论：通用记忆必须是多 substrate/多 agent 按角色组合+按 regime 路由。

## 创新点
1. 首个把 substrate 作为唯一受控变量的整体 harness 评测（7 家族×3 骨干×4 基准×26 指标）；2. 检索深度×注意力探针的机理性诊断（为什么同一次检索扫描对 QA 有益对决策有害）；3. 首次让写/读/管理成本可视化的效率仪表（E1–E11）；4. 三轴诊断收敛出"按 regime 路由 substrate"的系统级结论。

## 局限
纯文本任务（对话 QA/具身文本规划/代码），无多模态记忆；实现可能偏离原论文细节（作者自认）；未含生产级系统（Mem0/Zep/MemGPT 只在附录）；单次运行；"路由"是结论建议而非实现的系统。
