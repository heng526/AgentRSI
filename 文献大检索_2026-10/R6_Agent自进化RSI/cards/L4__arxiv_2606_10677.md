# Infini Memory: Maintainable Topic Documents for Long-Term LLM Agent Memory (2026, arXiv 2606.10677, Infinigence AI + 清华 + 上交)

## 问题与动机
- 持久记忆=跨会话存活、可写/可更新/可查询的外部可编辑状态。现有系统四大复发失败模式：(1) 记忆碎片化——同一用户/任务/事件的证据散布在孤立小记录中；(2) 记忆冲突——append 式存储让新旧版本并存可被同时召回；(3) 压缩损失——摘要丢失时序与来源线索；(4) 检索不足——单次向量/关键词/top-k 返回缺局部上下文的"碎片"，不足以支撑时序接地推理与多跳。
- 立场：持久记忆是生命周期维护问题，写/维护/读三个操作耦合；拒绝两个极端（孤立记录 vs 单一日志），也拒绝强制依赖向量库/图数据库（backend-light、可读可编辑可移植）。

## 方法拆解
- **表示**：记忆=主题文档库。每文档=元数据头 {id, summary, token_count, created_time, update_log, aux}+层次化正文（topic/subtopic 标题组织无序列表条目）；每条目前缀可解析签名 <seq=…, time=…, source=…>（seq 单调递增；source=AI 标注模型产出；可扩展实体类型/命名空间/敏感级）。三条实践收益：摘要与正文同步刷新；时序与来源线索随条目在重写/拆分/合并中迁移；seq+time 为"取代过时条目/显式删除规则"提供排序依据——**修订关系显式化**。
- **缓冲写入+固化**：新记忆先进 CURRENT 缓冲（append，不动主题库；保短程连贯便于局部去冗余/解矛盾）；达 5000 token 或时间阈值即 flush→重写为 REWRITE_CURRENT 归一化草稿（聚合相邻相关条目为带 seq 区间的语句、删冗余、标"取代早期条目"的更新关系）→规划器把块路由进主题库（扩展现有主题则插入对应区域；改变既有事实则记录更新关系并重写局部上下文；不合任何维护范围则建新主题）→周期性 split（>5000 token）与 merge（<1000 token 按摘要相似度）并刷新摘要元数据。固化前缓冲内容仍可被检索，避免"抽取-可检索"间隙。
- **读**：两变体——H（LLM 摘要选文档+BM25 分区检索）；A（agentic：LLM 控制 grep/grep_doc/search/list_docs/read_lines 等记忆工具，最多 7 轮，先广搜定候选区、局部 pattern 验证精确匹配、行读扩展上下文，停止条件为 agent 判定充分/迭代上限/证据预算/无新证据；不足时 BM25 兜底为 recall guard）。证据集合含文档级/标题块/行区间；CURRENT 未固化条目始终参与检索。
- **训练方式**：无训练；gpt-5-mini 骨干+gpt-5 LLM-as-Judge 判分。

## 数据与实验
- MemoryAgentBench 四能力（AR 准确检索/TTL 测试时学习/LRU 长程理解/SF 选择性遗忘），7 基线同 4096-token 切块。
- 主结果：Infini Memory-A overall 64.7%，超最强基线 19.2 个点（REMem 38.6；HippoRAG-v2 45.5、LightMem 34.2、MemGPT 31.2、MemoRAG 33.5、Mem0 25.0、RAPTOR 29.8）；四能力全领先：AR +12.5、TTL +4.4、LRU +25.4、SF +26.5。A 相对 H（61.3）+3.4，最大增益在 SF（+7.0，显式时序/来源线索帮助追踪修订事实）。
- **FC-MH 关键发现**：FactConsolidation 单跳 81.0% vs 多跳 58.0%——写时固化只能解决文档内单跳遗忘（重写阶段在主题文档内按新近性覆盖）；多跳遗忘的推理链跨多个不同时间更新的文档，没有单一重写能强制跨文档一致性，缺任一跳即级联失败（MemoryAgentBench 作者报告 o4-mini 从 6K→32K 上下文时 FC-MH 从 80.0% 掉到 14.0%）。
- 消融：结构维护（写时修订+拆并）与迭代证据检查贡献互补方面；拆分阈值敏感性分析。

## 创新点
1. 把持久记忆表示为"可维护的主题文档"——以纯文本+词条级 <seq,time,source> 签名实现免向量库/图库的显式修订关系与来源追溯。
2. 缓冲-固化分离：写频与维护范围的错配治理（缓冲保短程连贯、批量归一化、规划器路由+局部重写），避免 eager 维护的不稳定编辑。
3. 工具化 agentic 检索（7 轮内迭代检查/扩展证据），并在 SF 上验证"显式修订元数据"的直接价值。

## 局限
- 作者自认 FC-MH 是结构性极限：写时固化无法强制跨文档一致性——**多跳事实修订（跨文档错误传播）无机制解**，这正是我们"跨任务/跨文档错误定位修复"的切入点。
- 纯文本；主题路由/拆并阈值（5000/1000 token）手工设定；agentic 检索增加测试时算力。
- 修订靠写时 recency override，无事后审计：若写时错误判定"取代"，后续无检测手段。
- 无任务执行维度（QA benchmark），无进化/学习。

## 与本选题关系
- **撞车风险：低-中**。
- **overlap**：①四大失败模式（碎片化/冲突/压缩损失/检索不足）可作为我们记忆错误分类学的参照；②词条级 seq/time/source 签名=轻量 provenance，与我们的证据链溯源兼容；③FC-MH 的"跨文档一致性无法在写时解决"是"错误跨单元传播需专门定位修复机制"的文本域实证。
- **difference_from_ours**：Infini Memory 的维护全部发生在写时（固化管线），无任务信号驱动的事后发现与修复；跨文档多跳修订正是其公开短板（81.0→58.0）；无多模态、无策略进化。引用定位：作为"写时维护范式上限"的证据——我们主张把维护延伸到读后/任务后，用跨任务证据修复写时遗留错误。
