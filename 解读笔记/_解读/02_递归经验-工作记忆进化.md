# 递归经验-工作记忆进化：面向长时程 Agent Harness 的递归自改进
# Recursive Experiential–Working Memory Evolution for Long-Horizon Agent Harnesses

## 二、一句话总结

Recuris 把递归自改进（RSI）限定在冻结 LLM 之外的一个"记忆控制层"上：任务内由工作记忆（WM）维护经证据校验的任务状态、并据此触发对经验记忆（EM）中技能的调用，任务间由一个固定的 Meta-Agent 读取结构化执行轨迹、把每次失败归因到具体的记忆组件、只对被牵连的组件打补丁，并通过固定的验证门控决定是否采纳，从而形成"记忆塑造行为→行为产生证据→证据进化记忆"的有界递归循环，在 4 个长时程基准 × 10 个模型上于 37 个完成的"模型-基准"配对中改进了 35 个。

## 三、研究问题与动机

论文的核心问题是：**长时程任务中的递归自改进为什么难以实现，以及应该在哪一层实现**。

动机来自三个观察：

1. **长时程执行中记忆机制是静态的**。随着交互历史增长，agent 会丢失未完成目标、调用与当前状态不再对齐的技能。经验会积累，但 harness 组织、选择、改进这些经验的机制基本不变，这是 RSI 的核心障碍。
2. **现有经验记忆方法的检索锚点不可靠**。要么从初始指令检索（无法覆盖执行中途才出现的需求），要么从完整交互历史检索（混杂已完成步骤、过时信息与执行噪声）。根本限制不是"缺少有用经验"，而是"缺少一个紧凑可靠的任务状态来持续对齐经验与当前需求"。
3. **从最终成败学习无法定位修复点**。只看成功/失败信号能知道"出了问题"，却不能判断修复应落在存储的技能、被追踪的任务状态、技能调用机制还是进度校验器上，因此记忆更新往往粗粒度、弱指向。

作者的立论是：**工作记忆（WM）提供了缺失的状态表示**。WM 追踪进度与未解决目标并据此选择 EM 中的技能；技能执行后由环境反馈验证进度并更新 WM，形成"任务状态→技能选择→执行反馈→更新状态"的闭环。更重要的是，这个耦合把 harness 执行本身变成了结构化证据，使失败可以定位到具体组件，从而支持"EM-WM 耦合 → 结构化证据 → 失败定位 → 定向记忆进化"的核心逻辑。

## 四、方法详解

### 4.1 问题设定与技能记忆架构

agent harness 包裹一个**冻结 LLM** π_θ 与工具集 T。给定任务 x，第 t 步维护交互历史 h_t 与工作状态 w_t，调用策略选出一组经验技能 E_t，然后模型产出动作并接收观测：

- a_t ~ π_θ(· | x, h_t, w_t, E_t)，o_t = Env(a_t; T)。θ 全程不动，harness 行为的改变全部来自外部记忆控制机制。

在第 k 轮进化时，技能记忆表示为四元组 **M_k = (E_k, W_k, ρ_k, C_k)**（公式 2）：

- **E_k 经验记忆**：以 Anthropic agent-skill 格式存放可复用技能；
- **W_k 工作记忆规范**：定义状态 schema 与更新提案方式，用于维护任务级实例 w_t；
- **ρ_k 调用策略**：决定在哪些执行事件触发检索、E_k 中哪些条目进入上下文；
- **C_k 校验器集合**：检验观测是否支持提议的状态变更。

这四个组件构成"进化中的记忆控制层"，也就是 Recuris 的**补丁空间**。补丁按编辑粒度限定范围：每次编辑必须绑定一个被诊断出的失败、且只改该失败归因到的组件（一轮可以触及多个组件，但每个编辑都是组件限定的）。基础 LLM、工具、Meta-Agent、定位与打补丁流程、验证门控等外部机制全部固定——递归只发生在记忆控制层内部。

### 4.2 任务内：经验-工作记忆耦合（EM–WM Coupling）

**(1) 结构化工作状态**。harness 在 W_k 规范下从任务初始化 w_0。每个目标条目记录：内容、状态（pending / done / blocked 三选一）、支撑证据、可选的阻塞原因。w_t 因此随时暴露"已完成什么、还欠什么、哪些观测支撑已记录的进度"。

**(2) 状态锚定的技能调用（State-Grounded Skill Invocation）**。在定义好的执行事件上触发检索：E_t = ρ_k(x, w_t, e_t, E_k) ⊆ E_k（公式 4），其中 e_t 是执行事件。调用策略是一个"投递器（deliverer）"家族，每个投递器由 (w_t, e_t) 上的触发谓词与 E_k 上的检索键定义。论文实例化两个：

- **调用时投递（Call-time invocation）**：当 agent 起草一个会改状态的工具调用时触发，检索键就是该调用的工具名。被起草的调用**不执行**，harness 返回一个合成的 "not-executed" 结果，使检索到的技能在任何改状态动作发出之前就进入上下文。τ2 两个域使用此投递器。
- **边界投递（Boundary invocation）**：在轮次边界、按工作状态谓词触发，不依赖工具。Terminal-Bench 2.1 的记忆用 first_turn 谓词，在尝试开始时一次性供给技能。

关键点：LLM 仍然接收交互历史来产出动作，但**哪些技能到达它由 harness 在执行事件上决定**，而不是让模型自己从历史中挑。由于 ρ_k 本身是 M_k 的组件，触发谓词与检索键也在进化范围内。

**(3) 证据锚定的状态更新（Evidence-Grounded State Update）**（公式 5）：

- 提案：ŵ_{t+1} = U_{W_k}(w_t, a_t, o_t)——工作记忆规范提出下一状态；
- 校验：c_t = C_k(w_t, ŵ_{t+1}, a_t, o_t)——校验器集合对照观测评估提案；
- 提交：w_{t+1} = K(w_t, ŵ_{t+1}, c_t)——K 是执行 harness 中固定的提交规则，**只提交观测支持的变更**。

校验器 C_{k,g} 是目标 g 的显式完成谓词，评估的是工具/环境返回结果（如结构化工具回执），而不是模型自己声称成功。目标只有当谓词返回 1 才从 pending 变 done；"调用过技能"或"尝试过工具调用"不构成完成证据。若观测不支持提案，目标保持 pending 或转为 blocked。若校验器错杀了一个真实完成（false-pending），该决策记录在 c_t 中，之后可被定位到 C_k 作为修复目标。

任务级闭环（公式 6）：w_t --ρ_k--> E_t --(π_θ, T)--> (a_t, o_t) --(U_{W_k}, C_k, K)--> w_{t+1}。

**(4) 结构化轨迹**。连接两个循环的产物是轨迹 Γ_k = (x_k, {w_t, E_t, a_t, o_t, ŵ_{t+1}, c_t, w_{t+1}}_{t=1..L_k}, y_k)（公式 3）。与原始轨迹 τ 不同，Γ 把每个动作/观测与触发技能调用的状态、提议的状态更新、以及接受/拒绝该更新的证据绑定在一起。

### 4.3 任务间：有界技能记忆进化

**(1) 基于轨迹的失败定位**。对第 k 轮的失败运行，固定的定位阶段输出诊断：D_k = A_fixed(Γ_k, M_k) = {(f_j, z_j)}，f_j 是被诊断的失败，z_j ∈ {E, W, ρ, C} 是归因组件（公式 7）。归因语义：归到 E 表示技能缺失或有缺陷；归到 W 表示目标遗漏、状态字段不合适或状态更新提案错误；归到 ρ 表示技能调用缺失、过晚或不相关；归到 C 表示"该过的没过/不该过的过了"。论文强调这是**修复决策而非因果断言**——把失败归因到"局部干预最可能奏效"的组件。

**(2) 组件限定打补丁**。对每个被牵连组件各提一个编辑，合成单个候选：Δm_z = P_fixed(Γ_k, M_k, D_k, z)，M+_k = M_k ⊕_{Z_k}{Δm_z}（公式 8）。⊕_{Z_k} 算子恰好只改被牵连组件，其余原样复制。补丁可以：增改 E 中技能、改 W 的状态字段或更新提案、调 ρ 的触发谓词或检索键、改 C 的完成谓词。

**(3) 验证门控采纳**。候选不直接上线。固定门 G_fixed 在失败源任务 x_k 与留出开发集 D_dev 上比较 M+_k 与 M_k，只有"修复了目标失败且满足预设回归标准"才接受：M_{k+1} = M+_k（若 G=1），否则维持 M_k（公式 9）。开发集刻意包含**锚点任务**（当前记忆已能解决的任务），防止"修好一个、弄坏别个"。任务划分在运行前冻结：evolve split 供定位与打补丁，dev split 只给门用，test split 从不进入定位、打补丁或采纳环节。

**(4) 有界递归进化**（公式 10）：M_k →Γ_k→(A_fixed)→ D_k →(P_fixed, ⊕)→ M+_k →(G_fixed)→ M_{k+1} →Γ_{k+1}→ …。之所以称"递归"，是因为每次采纳会改变未来执行的记忆控制层，新的行为又产生能触发后续更新的证据；采纳的修改不只修复当前失败，还改变之后状态如何被表示、技能如何被调用、进度如何被校验、失败如何被观察。递归是有界的：除 M_k 外的一切固定。

**(5) 测试时适应模式**。同一台机器收窄到单任务：给定一个任务与 N 次尝试预算，隐藏验证器只返回一个比特；Meta-Agent 只拿到任务指令、失败轨迹与这个比特，永远看不到验证器、测试或期望输出（由 harness 强制）。失败后对经验记忆提局部更新再重试，首次成功即停。

## 五、实验与主要结果

**设置**。四个长时程基准：τ2-Bench 的两个工具使用域——τ2-Retail（114 任务）与 τ2-Airline（50 任务，双控制环境、只有环境验证器给满奖励才算成功）；SkillFlow（166 任务、20 个任务族，族内任务共享一条执行流程，每个任务自带验证脚本、程序化打分）；Terminal-Bench 2.1（87 个终端任务，用于测试时适应实验）。指标除任务成功率外，还分别报告 read-action recall（读动作召回）与 required-write recall（必需写动作召回），以区分"知道该做什么"与"真做了"。**部署模型**为 doubao-seed-2-0-pro（刻意选中型而非前沿）：进化循环只在它身上跑，每基准构建一份技能记忆；目标模型覆盖三个开源家族（Qwen3、Granite、gpt-oss）与三个前沿模型（Gemini 3.7 Flash、GPT-5.6 Sol、Claude Opus 5）。任何地方都不更新权重；每任务独立尝试 k=4 次，单次上限 200 步、连续 10 次工具错误。Meta-Agent 基于 Claude Code 构建（Run B/C 用 DeepSeek Harness 复刻），从不修改、从不接触测试集。

**总体性能（Table 1）**。35/37 个完成配对提升。亮点（avg@4 成功率）：

- τ2-Retail：部署模型 Doubao-2.0-Pro 58.1→81.4（+23.3†）；GPT-5.6 Sol 58.3→76.1（+17.8†）；Claude Opus 5 72.4→87.9（+15.6†）——比评估中任何模型不带 Recuris 的最好成绩还高 9.7 分；GPT-OSS-20B 50.6→60.8（+10.2†）；Granite-4.1-3B 9.7→23.0（+13.4†）。
- SkillFlow：Qwen3.6-27B 42.2→58.7（+16.6†）；Qwen3.6-35B 35.3→48.8（+13.5†）；部署模型 34.6→51.4（+16.8†）。
- τ2-Airline：GPT-5.6 Sol 79.0→86.0（+7.0†）；其余多数为 +1~+5 的非显著增益。
- Terminal-Bench 2.1（测试时适应）：全 87 任务 avg@4 46.1→48.9（+2.9，CI 含零）。
- **收益来自"会自我修订的记忆"而非"记忆本身"**：固定不变的 M0 相对裸 agent 的贡献在四个目标模型上与零不可区分（附录 B：点估计两正两负、区间全含零），因此 M0 之上的部分属于进化。

**长时程可靠性**。按任务内在完成时长把 τ2-Retail 分四分位（用所有变体的通过轮次中位数，避免以变体自身实现的长度分层造成循环），Recuris 在所有四分位领先 base agent +17.0 至 +44.7 分，最长的 >31 轮任务上增益 +32.2。**长时程失败是执行问题而非检索问题**：所有变体在所有分位的 read-action recall 都在 88.0–97.9%；差距全在写路径——Recuris 的 required-write recall 高出 26.7 分；base agent 在需要写的回合中 42% 一条写都没执行（Recuris 为 16%）；四个变体首次正确写的轮次中位数完全相同（18），说明改变的"是否行动"而非"何时行动"。六类长时程失败模式相对降幅：幻觉式完成 ↓86%、遗漏写 ↓80%、零写回合 ↓62%、首次工具调用错误 ↓44%、错误级联 ↓24%、遗漏读 ↓20%。

**跨模型迁移（Table 7）**。在 τ2-Retail 上，一份由中型部署模型进化出的记忆原封不动地带给未参与构建的前沿模型：GPT-5.6 Sol +17.76† [+11.84, +23.90]、Claude Opus 5 +15.57† [+10.96, +20.39]、Gemini 3.7 Flash +4.82 [−0.22, +10.09]；τ2-Airline 上 GPT-5.6 Sol +7.00†、Opus 5 +1.0、Gemini −1.5。它不是弱模型的拐杖：同一个包在部署模型上 +23.3，而最强的目标模型反而到达最高终点（87.9 对部署模型上的 81.4）。

**计算与上下文**。模型控制式（全技能库常驻上下文）首调用多 3,111 个 prompt token（8,274 对 5,632），低 18 分，每个成功多花 46% 的 token（146,849 对 100,865）——更多上下文反而更差。

## 六、消融与分析

1. **EM/WM 耦合消融（Table 2，τ2-Retail）**：base 58.1；仅 EM 60.1（+2.0，ns）；仅 WM 82.0（**+23.9†**）；模型控制式调用 65.6（+7.5†）；EM+WM（完整 Recuris）83.6（+25.4†）。结论：**承载水平的是经验校验的工作状态**；经验记忆的价值是"调用条件化"的——Recuris 比持有字节相同技能库的模型控制式高 18.0 分 [+11.6, +24.6]。τ2-Airline 各变体区间全含零（50 任务统计功效不足），仅作方向参考。
2. **域内关键机制双重分离（Fig 6）**：工作状态由四个机制维护——写前审查（write review）、事后真值守卫（truth guard）、状态看板（status board）、门控终止（gate termination）。Airline 去掉 write review 掉 13.5 分†（status board 无损失）；Retail 恰好相反：status board 掉 17.3 分†、write review 仅 −0.7（ns）。**关键机制是域的属性而非架构的属性**——设计期固定分配组件预算必然在某些域出错，这正是需要"从失败轨迹读取修复目标"的原因。有趣的是 truth guard 虽拒绝了 172 个不成立的完成声明，却从未显著影响结果：写已执行、环境已变，事后审计记录不了错误也撤销不了。
3. **调用控制 vs 技能内容（Table 3）**：持有字节相同的 10 技能库，Recuris 成功 83.6、写召回 82.4、每回合遗漏必需写 0.121、每成功 101k token；模型控制式 65.6 / 61.1 / 0.417 / 147k。模型控制式甚至低于完全不带技能的 WM-only（82.0）。增益的形态是**覆盖而非速度**：首次正确写的中位轮次四配置均为 18；回合内错误会复利——一旦一次必需写错，后续写出错概率在任何配置中都超 60%，而 Recuris 最少进入该状态。
4. **结构化轨迹改善失败定位（Table 4）**：向正常包的一个组件注入已知故障，让固定裁判在三组证据下指认组件。仅凭结果 macro 13.0%（低于 33.3% 常数底）、原始轨迹 37.0%、结构化轨迹 Γ **64.8%**（macro-F1 63.4；精确率 27.6→64.4）。ρ 类故障（该调用未调用）是"没有发生的事件"，转录中无迹可寻：前两组证据下 0.0%，Γ 下 38.9%。C 类无法测试：去掉校验器在 τ2-Retail 上通过率零变化，说明其"已收录案例"只是解码噪声。
5. **递归进化的一致留出收益（Table 5）**：τ2-Retail 冻结划分 16 evolve / 12 dev / 86 test。M0 54.07；同包重跑差 +0.00 [−6.98, +7.27] 定标仪器分辨率。三次进化运行的最终包全部以排除零的区间超越 M0：Run A（Claude Code）+9.01→+11.92（第 2 轮复利叠加，第 3 轮持平）；Run B（DeepSeek Harness）+10.47→+10.76，第 4 轮 +3.78 不显著——但其轨迹显示记忆在 0/86 留出任务上被调用（对比同谱系第 2 轮的每回合 18.50 次调用），是"绑定断裂"而非收益递减；Run C 渐进采纳 M1 +10.47、M2 **+17.44**、final +9.30。九个包的成功增量与写召回增量相关 r=0.97，说明收益是执行性的。
6. **两套 Meta-Agent 实现收敛（Table 6）**：把 Meta-Agent 从 Claude Code 整体换成独立重写的 DeepSeek Harness，配对差 −1.45 [−7.85, +4.65]（p=0.72），落在 M0 重跑噪声带内；且两实现独立蒸馏出**同一组件家族**：追踪服务请求授权的 WM 字段、执行门检查、一组反升级技能。循环学到什么由证据决定，而非由承载诊断的机器决定。
7. **门控保安全**：被采纳的更新在 42 个锚点任务上只破坏 4 个（9.5%），显著低于同包重跑的 25.9% 解码噪声（精确二项 p=0.013），且无一降到 0；18 个被拒候选的开发区间全部含零。一次关掉 dev 门的第 4 次进化运行中，门在第 r 轮判为 −10.4 与 −6.2 的两个补丁，在冻结测试集上从未显出害处（三包全部 +14.5~+18.0）——门偏保守而非误伤。记忆只增不减：8 个被采纳补丁新增 51 个技能、修订 2 个、零废弃，17 对近重复技能共存；但没有任何单个技能承载收益（逐个移除五个/两个/最大的程序技能，结果波动 −2.3~+1.7 全不显著）——进化出的记忆冗余而不脆弱。
8. **跨任务迁移的条件性**：来自 16 个训练失败的包在 86 个从未见过的任务上 +9.01~+17.44†，且在 78–86/86 的任务上被真实调用（每回合 2.45–18.50 次）；唯一在 0 个任务上被调用的包也是唯一未超 M0 的包——迁移不是泛化提示效应。但 τ2-Airline 两条谱系在各自留出集上与零无法区分：留出集基线已高达 73.0%/81.0%，"值得修的失败"在 train/dev 分配时已用尽。迁移被严格限定表述为：**在留出任务仍含有该记忆所修失败类型之处成立**。
9. **测试时适应的诚实分解（Table 8/9，Terminal-Bench 2.1）**：1 次尝试基线 30/87（34.5%）；+种子记忆 28/87（−2.3，p=0.824）；+种子记忆重试 4 次 51/87（+26.4，p<10⁻⁴）；+测试时适应 53/87（+2.3，p=0.774）——**标题数字由尝试预算解释**。换用重试买不到的每尝试指标：在 56 个学到技能的任务上 avg@4 17.4→21.9（+4.5，四组切分方向一致但区间均含零）；单个任务 16 次展开下裸 agent 解 8 次、种子记忆 7 次、适应记忆 15 次（p=0.006）。调用经内核计数器验证（53/57 次到达 agent），93 个学到技能经事后审计无一含任务特定值。
10. **案例研究**：(a) τ2-Retail Task 91——口头确认不关闭任何目标，Recuris 把退回/换货目标保持 pending 直到技能引导的工具调用返回匹配回执；(b) 同品交换失败被归因到 EM 工作流，补丁改为在交换前检索有效变体 ID，采纳后在未见过的匹配任务上 0→100%；(c) Run A 第 2 轮的门记录极具信息量：两个候选分别把修复率 .214→.393 与 .214→.571，却因 12 任务 dev 划分给出 30+ 点宽的区间而被拒（net −2.1 与 +6.2 均 REJECT），其中第二个后来在 86 任务留出集上结算为 +11.92†——门不是好坏过滤器（在该证据预算下不可能），而是"拒绝承诺证据无法分辨的东西"的规则，其保守性的成本在预注册的留出评估处收回；(d) SkillFlow 上模板替换显示程序的分量：weighted-risk-assessment 规范模板 0/8 对族内选中模板 7/8，embedded-data-repair 4/8→8/8（20 族中 6 族被覆盖）。

## 七、局限性与批判性评述

1. **统计功效的边界**。τ2-Airline 仅 50 任务，耦合消融的每个区间都含零，Airline 结论只是"方向"；Terminal-Bench 的学习效应在所有聚合指标上区间含零，作者自己也只敢称方向。基准规模直接限制了可断言的结论强度。
2. **验证门偏保守且分辨率不足**。12 任务 dev 划分无法分辨真收益：+6.2 的候选被拒、事后结算 +11.92。门保护了锚点能力但以漏收为代价；进化轮次并不单调（Run C 第 4 轮回吐大部分收益），"复利"叙事只在部分谱系成立。
3. **SkillFlow 无留出任务划分**。技能按族在自身任务上选择，是 in-sample 的；其主表结果只能解释为跨模型迁移而非跨任务泛化，与 τ2 的证据类型不同质。
4. **递归的"有界"既是安全性也是上限**。所有进化都发生在四个记忆组件内，harness 本身（如 truth guard 这类事后机制无用的结构性问题）不能被循环修复；案例中 Meta-Agent 归因给"harness 本身"的失败簇直接放弃修复。
5. **记忆单调增长无剪枝**。51 个新增技能、17 对近重复无人清理，作者把剪枝算子留作未来更新集；长期演化的记忆膨胀与检索冲突未受检验。
6. **C（校验器）组件的进化价值未被验证**。因 τ2-Retail 上校验器不 bind，注入实验只得三个类；"四组件可进化"的完整主张只测试了四分之三。
7. **单一来源记忆设计**。所有记忆都在 doubao-seed-2-0-pro 的失败上构建，虽然换来跨模型可迁移性，但也意味着针对其他模型特性分布的适配未知；SkillFlow 的迁移随规模走、τ2 的"纪律"迁移不随规模走，其机制解释（程序 vs 纪律）仍偏叙事。
8. **长时程分层是观察性再分析**而非受控操纵，作者自己也如此承认。
9. 依赖环境提供可校验的回执/验证器；在缺乏结构化工具回执的环境中，"证据锚定状态更新"的可行性会下降。

## 八、对读者研究的启发

读者方向为"多模态 Agent 长时程记忆 + 递归自改进 RSI / harness 进化"，本文是最直接的对标工作，可借鉴点与研究缺口如下：

1. **"记忆控制层作为冻结模型的可训练表面"这一层位选择**。把 RSI 限定在外部记忆的四个组件（E/W/ρ/C）上，换来可归因、可回滚、跨模型可移植的改进——这套"窄层递归 + 宽层固定"的设计模式可直接移植到多模态 harness：例如把视觉感知缓存、帧/片段状态追踪、感知工具调用策略、观测校验器作为四组件，让多模态长视频 agent 在冻结 VLM 上递归进化。
2. **"状态锚定调用"优于"内容堆叠"**是全文最强的可迁移结论：技能/经验的价值是调用条件化的，全库常驻反而更差且更贵（+3,111 token、−18 分、+46% 成本）。多模态场景同理：视频证据片段、感知技能、跨模态提示都应由"已验证的多模态任务状态"触发注入，而非靠模型自选或一次性全给。
3. **结构化轨迹是失败定位的前提**：Γ = (w_t, E_t, a_t, o_t, ŵ, c, w') 的记录格式值得照搬；64.8% 对 13.0% 的定位对比给出了"可进化性取决于可观测性"的量化论据。多模态轨迹还需加入感知事件（检测/检索/帧选择）的事件流，这是一个明确的扩展缺口。
4. **评估协议本身是贡献**：预注册三重划分（evolve/dev/test）+ 锚点任务 + 任务聚类配对 bootstrap + A/A 重跑定标 + McNemar 检验 + "以仪器分辨率解读差异"的纪律，适合作为任何 RSI/harness 进化研究的模板；其"预算匹配的配对对照"（共享首轮 rollout）设计可直接用于评估多模态 agent 的测试时适应。
5. **研究缺口**：(a) C 类校验器的进化与测试需要"校验真正 bind"的域——多模态感知验证（如帧证据与声明的一致性检查）可能是天然场所；(b) 记忆剪枝/合并算子（文中 17 对近重复未处理）；(c) 多基准共享进化（本文每基准一份记忆）；(d) 长时程因果操纵实验而非观察性分层；(e) 在无结构化回执的环境（开放网页、真实 GUI）中实现证据锚定状态更新；(f) 跨模型的"程序 vs 纪律"迁移机制的更精细理论——文中 SkillFlow 按规模迁移、τ2 不按规模迁移的现象值得建模。
