# KARMA：用长短期记忆系统增强具身 AI 智能体
# （KARMA: Augmenting Embodied AI Agents with Long-and-short Term Memory Systems）

## 一、基本信息

- **作者**：Zixuan Wang（王子轩）、Bo Yu、Junzhe Zhao、Wenhao Sun、Sai Hou、Shuai Liang、Xing Hu、Yinhe Han、Yiming Gan（通讯作者）
- **机构**：中国科学院自动化研究所（CASIA）、深圳人工智能与机器人研究院（AIRS）、阿里巴巴集团、中科院计算技术研究所（ICT, CAS）、北京理工大学、中国科学院大学
- **发表信息**：arXiv:2409.14908v2（2024 年 9 月提交，ACL/学术期刊排版格式，全文 19 页）
- **代码链接**：https://github.com/WZX@Swarm@Robotics/KARMA/tree/master（原文如此，实为该组织下的 KARMA 仓库）；实验视频：https://youtu.be/4BT7fnw9ehs
- **实验平台**：AI2-THOR 仿真器 + 真实移动操作机器人（UR3 机械臂 + 六轮底盘）

## 二、一句话总结

KARMA 为室内家庭任务具身智能体设计了一个"即插即用"的双记忆系统——以非易失的 3D 场景图（3DSG）作为长期记忆、以带缓存式替换策略（W-TinyLFU）的易失短时对象记忆作为短期记忆，通过向量检索将两者注入 LLM 规划器的提示词，从而在 AI2-THOR 长序列任务上将成功率提升至基线的 1.3–2.3 倍、执行效率提升 3.4–62.7 倍。

## 三、研究问题与动机

论文的出发点是：家庭场景中的机器人任务往往是一串在时间与逻辑上相互依赖的指令（如"洗苹果→切苹果→洗番茄→放到盘子里混合"），后续指令强烈依赖前序任务改变过的对象位置与状态。即便用 GPT-4o 这类强 LLM 做规划器，当上下文里需要塞入大量任务描述与示例时，LLM 也会"模糊掉关键细节"，例如忘记之前用过的苹果被扔进了垃圾桶，导致智能体不得不重新探索环境、反复调用 LLM，造成成功率低与效率低下。

作者指出现有记忆增强方法的三个缺口：(1) 具身领域多数工作只存"过往经验/历史动作"，缺乏对环境静态结构与即时对象状态的结构化区分；(2) "永久保存一切"会带来不可承受的存储开销，而"每次重启就清空"又丧失长期能力；(3) 记忆该替换哪一条没有共识——多数方法用遗忘曲线（MemoryBank）或简单 FIFO（MemGPT），缺少结合场景的更新机制讨论。KARMA 用"长期记忆管环境、短期记忆管最近交互、用缓存命中率驱动替换策略"来同时回应这三点，并把计算机体系结构中成熟的缓存思想（LFU/W-TinyLFU、命中率）迁移到具身记忆管理上，这是全文最有辨识度的立场。

## 四、方法详解

### 4.1 问题形式化

用户给智能体一系列指令 H = {I₁, I₂, …, I_T}，每条指令 I 可分解为有序子任务集合 T = {T₁, …, T_K}；智能体可执行的技能集 S ∈ {S_manipulation ∪ S_navigation}（如 Explore()、OpenObject()），由 LLM 通过预定义 Python 风格 API 调用。

### 4.2 长期记忆：3D 场景图（3DSG）

- **存储形式**：层级拓扑图 G = (V, E)，V 分 3 层（K=3）：Floor（楼层）—Area（区域）—Object（物体）。区域节点均匀分布于可达区域，世界坐标由仿真器给出（真实世界可用 Faster R-CNN 等检测）；若两个区域节点互相可达则连边；不可移动物体作为对象节点挂到对应区域，编码体积、3D 位置等属性。
- **选择 3DSG 而非 2D 语义地图/体素的理由**：拓扑结构稀疏，可缓解累积漂移（避免传统 SLAM 回环检测的漂移误差），扩展地图时只需增删节点；且再强的多模态 LLM 也难从 2D 地图读出几何关系，3DSG 序列化成文本后 LLM 可直接解析。
- **使用方式**：整个 3DSG 被序列化为文本直接放进 prompt，例如 `{name: node_1, type: Area, contains: [bed, table, window, ...], adjacent nodes: [node_2, node_8], position: [2.34, 0.00, 2.23]}`，边写作 `{node_1 ++ node_2}`。长期记忆非易失、任务无关、低频更新（仅在环境布局改变时更新）。

### 4.3 短期记忆：易失的对象记忆单元

- **写入**：任务执行中智能体拍图后，用 VLM（GPT-4o）做任务条件化的图像分析——以 Chain-of-Thought 提示从图像中提取"感兴趣对象（OOT）"的状态（状态枚举为 heated/cooked/sliced/cleaned/dirty/filled/used up/on/off/opened/closed/none），再与仿真器给出的世界坐标、原始图像一起构成一条记忆单元 `{objectType, objectId, position(x,y,z), state, imagePath}`，类似缓存中的一行。
- **向量化**：由 text-embedding-3-large 将记忆单元转为向量供检索。
- **易失性**：智能体每次启动即刷新，只保留"最近用过/见过的对象"的即时信息。
- **检索**：对当前指令 I 做嵌入，在短期记忆全体向量中取余弦距离最小的 top-K 条，其文本内容作为上下文拼入 prompt（长期记忆则整体序列化注入，短期记忆只选条目）。

### 4.4 规划器

LLM（GPT-4o）收到完整 prompt：角色设定 + 技能 API（GoToObject/PickupObject/PutObject/SwitchOn/SwitchOff/OpenObject/CloseObject/BreakObject/SliceObject/ThrowObject/Explore/ToggleOn/ToggleOff，均参数化为 Python 函数并附示例）+ 任务分解 few-shot 示例 + 强调"利用记忆"的提示 + 指令 I + 检索到的短长期记忆，然后生成任务分解动作代码。例：指令"把苹果放进冰箱"，prompt 中的记忆 `{apple is in the trash}{apple is dirty}` 和拓扑图信息让 LLM 直接对垃圾箱区域排序探索，而不是全屋乱找。

### 4.5 记忆替换策略（核心贡献之二）

短期记忆容量固定、易满，作者引入缓存领域的**命中率（hit rate）**作为替换策略评价指标——查询能在短期记忆中找到所需记忆单元的次数占总查询次数的比例，命中率越高说明替换策略越好。比较三种策略：

1. **FIFO（改进版）**：队列满时淘汰最早入队者；改进点：若新单元的对象 ID 已在队列中，则原地替换同 ID 旧单元（合并语义），避免同一对象占多条。
2. **LFU**：淘汰使用频率最低者；完美 LFU 不可行，采用近似算法 **W-TinyLFU**。
3. **W-TinyLFU**：记忆分 window 段与 main 段（main 段再分 protection 段与 elimination 段的两段式 LRU）。新单元先进 window 段；需要淘汰时，在 window 段与 elimination 段中选出"淘汰后对整体使用频率影响最小"的单元。频率统计用计数布隆过滤器（counting Bloom filter）；为保持新鲜度，每加入一个单元全局计数器 +1，达到阈值 W 时所有计数器减半：cᵢ ← cᵢ/2（衰减机制，防止陈旧热点永久占据记忆）。

## 五、实验与主要结果

- **平台与实现**：AI2-THOR 仿真器（用其内置物体检测提供标签）；嵌入模型 OpenAI text-embedding-3-large；规划器与 VLM 均为 GPT-4o。
- **数据集 ALFRED-L**（自建，48 条高级指令）：从 ALFRED 抽取任务重组为长序列任务，附 AI2-THOR 户型图与每个子任务完成后的真值状态（如 INSIDE(apple,sink)=1、TOGGLEON(faucet)=1、State(apple,clean)=1）作为符号化目标条件。分三类：Simple（15 条，互不相关、序列长度 <5）、Composite（15 条，高度相关、需复用前序记忆）、Complex（18 条，松散相关、含模糊指代如"把红色食物放到盘子里"）。另有 **ALFRED-R**：从 ALFRED 随机采样长序列任务，专评替换机制。
- **基线**：LoTa-Bench（Modified，按 SMART-LLM 的技能集配置优化）、HELPER（Sarch et al.）、CAPEAM（Kim et al.）。
- **指标**：成功率 SR、记忆检索准确率 MRA、记忆命中率 MHR、减少探索比 RE = F_reduced/F_total、节省时间比 RT = T_reduced/T_total。

**主结果（ALFRED-L）**：
- Complex：KARMA SR=0.21 vs HELPER 0.09、LoTa-Bench 0.04（相对最强基线 2.3 倍提升），RT=0.690、RE=0.867（相对效率提升 62.7 倍）；
- Composite：KARMA SR=0.43 vs CAPEAM 0.33（1.3 倍），RT=0.687、RE=0.902（效率 3.4 倍），MRA=0.93；
- Simple：KARMA SR=0.42 vs HELPER 0.40（1.1 倍，因简单任务用不上短时记忆），RT=0.612（效率 2.3 倍）；
- MRA 上 Composite（0.93）是 Complex（0.42）的 2.2 倍，原因是"高热量食物"这类模糊语义让语义匹配模型天然吃亏。

**真实部署**：UR3 机械臂 + 六轮底盘，Google Cartographer 做 SLAM，夹爪相机图像经 LangSAM 分割与语义匹配定位目标，AnyGrasp 生成抓取位姿并规划手臂路径，验证 KARMA 可即插即用地迁移到真实机器人。

## 六、消融与分析

1. **去长/短期记忆消融**：去掉短期记忆，Complex/Composite 的 SR 分别下降 1.9 倍与 4.2 倍（0.21→0.05、0.43→0.22），但执行效率仅降 1.2/1.1 倍——短时记忆主要保成功率；去掉长期记忆，RT 大跌 2.7 倍（如 Simple 的 RT 0.612→0.002），SR 仅降 1.2 倍——长期记忆主要保效率（减少 LLM 生成的探索动作代码）。两者功能互补的结论清晰。
2. **替换策略对比**：总容量 10 条时，warm-up（占用率 >95%）后 W-TinyLFU [window=9, main=1] 命中率最高，优于 FIFO[10]；window 越大越能覆盖更宽时间范围、留住高频复用单元。
3. **容量-命中率关系**：FIFO 从 5 条扩到 25 条，命中率提升约 4.6（百分点）；W-TinyLFU 下 25 条比 5 条高约 3.9——容量越大命中率越高，但在同等容量下策略差异更关键。
4. **命中率→效率**：命中率与"减少探索比例"呈线性正相关（Fig.7），说明记忆命中直接转化为更少的 Explore 动作与更短执行时间，为"用命中率评估记忆系统"提供了因果证据链。
5. **真实世界部署**定性展示了记忆的存储-检索-复用闭环。

## 七、局限性与批判性评述

作者自己列出三条局限：(1) **理想仿真环境**——无其他智能体/人类干扰，真实世界物体数量远超仿真，检索与替换机制的有效性未受真实检验，也未测试对人为干扰的鲁棒性；(2) **缺乏生物学理论支撑**——短时记忆/替换只是借用了缓存设计概念与人类记忆的术语，人类记忆未必如此运作；(3) **开环规划**——记忆写入与规划均无反馈回路，记忆错误时没有纠正或驱逐机制。

我的补充批判：(a) 长期记忆只在"环境布局改变时"更新，但短期记忆里对象状态的变化并不会回写进 3DSG，两套记忆之间缺乏一致性维护，长期运行可能出现"图上说苹果在桌上、实际在垃圾桶"的矛盾，而论文没有处理这一冲突；(b) 状态识别完全依赖 GPT-4o 的 VLM 判断 + 仿真器真值坐标，真实场景中这两个信息源都有噪声，误差会沿记忆链累积；(c) 语义检索对模糊指令（"高热量食物"）失效的问题只是被指出而未解决，缺少重排序或 LLM 兜底检索；(d) ALFRED-L 仅 48 条指令、任务池小，命中率的统计意义有限；(e) 命中率虽与 RE 线性相关，但"命中率→成功率"的直接因果未被单独验证；(f) W-TinyLFU 的收益在图 4 中绝对值较小（约 0.15 vs 0.10 量级），工程意义需谨慎解读。

## 八、对读者研究的启发

读者的方向是"多模态 Agent 长时程记忆 + 递归自改进 RSI"，KARMA 至少有五点可直接借鉴：

1. **结构分层的双记忆范式**：把"环境静态结构（3DSG/拓扑图）"与"对象即时状态（短时单元）"分离，并分别以全量序列化 / 向量 top-K 检索两种方式注入 prompt——这个"长期=结构化世界模型、短期=缓存式经验"的二分法可作为多模态记忆系统的骨架；在 RSI 框架中，长期记忆天然适合存放"世界/技能的沉淀知识"，短时记忆存放"当前自改进循环的中间产物"。
2. **用缓存命中率作为记忆系统的一等评价指标**：命中率→减少探索→效率的线性关系给出了可量化、可优化的代理目标。做递归自改进时，同样可以定义"经验命中率"（自生成的经验在后续任务中被复用的比例）作为 RSI 收益的可测代理指标，替代笼统的"性能提升"。
3. **替换/遗忘策略工程化**：W-TinyLFU 的"频率衰减（计数器减半）+ window/main 两段 + 同 ID 合并"是一套即插即用的遗忘机制，可替代 RSI 系统里常见的 FIFO/遗忘曲线，尤其适合"高频复用的技能/经验应被保留、一次性观察应被淘汰"的技能库维护场景。
4. **记忆写入的任务条件化**：KARMA 写记忆时把"当前任务"喂给 VLM 来决定记什么状态——提示我们在多模态记忆写入端就应做任务相关性过滤，而非事后检索时再过滤。
5. **反馈闭环是最明显的改进空间**：论文承认开环（记忆错了不纠正）。一个直接的 RSI 化扩展是：给记忆系统加"验证-回写"循环——执行结果（成功/失败、真值状态）反向修正记忆条目并更新置信度，让记忆系统本身随经验递归自改进；这也可与"同 ID 合并"扩展为"同 ID 状态机的版本化更新"。
