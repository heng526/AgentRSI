# VideoHarness-RSI：冻结视觉语言模型下长视频理解的递归 Harness 自改进
# VideoHarness-RSI: Recursive Harness Self-Improvement for Long-Video Understanding with Frozen Vision-Language Models

## 一、基本信息

- **作者**：Guoyang Xu、Hao Chen，均为腾讯（Tencent）员工。
- **机构**：Tencent。
- **发表信息**：arXiv:2608.24302v2 [cs.AI]，2026 年 9 月 3 日提交（v2），Preprint，16 页。
- **代码链接**：https://github.com/Tencent/VideoHarness-RSI （承诺发布 seed-42 划分、逐题预测、完整搜索轨迹与上下文 sidecar 日志的可审计工件包）。

## 二、一句话总结

论文把"长视频理解"重新表述为一个**上下文构造问题**：在冻结的 VLM（Qwen3-VL-8B-Instruct）与固定回答接口之下，将"长视频+问题 → 有界多模态上下文"的映射本身作为一个可执行程序（harness）作为搜索对象，用外层"提议-执行-评估-保留"循环递归搜索上下文构造代码，从弱种子（均匀采样）能发现结构化程序、从强种子（手工 AKS harness）能继续推进已有前沿，最终选出的 CARDINALITYLEDGER 在 LVBench 留出集上 54.8%、在匹配累计视觉 token 成本下仍胜过更高容量的父代，并可零搜索直接迁移到 Video-MME 与 MLVU。

## 三、研究问题与动机

**问题背景**：长视频对 VLM 依然困难，即使底层模型很强——相关证据稀疏、时间上分散、被数千个无关观察包围，穷举呈现长视频不现实。因此长视频理解**部分是一个上下文构造问题**：性能不仅取决于 VLM 能推断什么，还取决于其周围系统选择让模型看到什么。

**现有方法的缺陷**：压缩、检索、外部记忆、时间导航、迭代证据获取等系统往往**同时改动多个组件**——证据表示、检索、工具、推理工作流甚至模型本身——导致无法分离"仅上下文构造程序一项能带来多少改进"。上下文构造程序本身难以作为一个独立的优化目标来研究。

**核心研究问题**：当底层 VLM 及其接口完全固定时，harness 能否**递归地**自我改进？这里"递归自改进（RSI）"被严格定义为：通过提议与任务评估对 harness **代码**的反复改进，而非对 VLM 参数或内在智能的改进。

**框架的三重贡献**：(1) 将长视频上下文构造形式化为冻结 VLM 周围的可执行 harness 优化问题；(2) 提供 propose–execute–evaluate–retain 的 VideoHarness-RSI 基线；(3) 提供围绕完整搜索谱系、逐题输出、执行轨迹、留出评估与上下文成本核算的可审计评估协议，使被搜索出的 harness 可以作为"程序"而非只有最终分数来研究。

## 四、方法详解

### 4.1 可执行上下文构造器（问题形式化）

设开发集 D_dev = {(V_i, q_i, y_i)}，M 为冻结 VLM，K 为最终视觉上下文约束。harness H ∈ H_exec 是可执行程序，将视频-问题对映射为有界多模态上下文：

- C_H = H(V, q; K)，ŷ = M(C_H, q)（公式 1）。

优化目标是开发集准确率下的最优构造器：H* = argmax_{H∈H_exec} (1/|D_dev|) Σ 1[M(H(V_i, q_i; K), q_i) = y_i]（公式 2）。M 的参数与解码配置固定，受控比较中每次 VLM 调用遵守同一 K。多阶段 harness 可做多次有界调用，因此**累计答题帧数可超过 K**——受控变量是"可执行上下文构造"，而非模型训练或单次调用视觉容量。

**分析性分解**（公式 3）：H(V, q; K) = Pack_H(Read_H(Write_H(V), q), K)。

- **WRITE**：构建可寻址表示（视频流、字幕列表、嵌入索引等）；
- **READ**：检索问题条件化的证据；
- **PACK**：排序并格式化供给 M 的有界上下文。

这只是一个上下文构造器的分析性分解，**不是三个分别优化的目标**；harness 可以在此路径上编辑、替换或组合行为，不强制任何特定的记忆、采样器或检索器。

### 4.2 递归 harness 搜索

在第 t 代，F_t 为在位准确率前沿，A_t 为存档（历史 harness 代码、分数、评估轨迹）。外层提议者充当自动设计者——**不直接做下游视频理解任务**，而是提议改动"决定冻结 VLM 看到什么"的 harness，生成可执行候选 {H_t,j} ~ P(F_t, A_t)（公式 4）。两个关键设计选择：

- 提议者**不被指派固定模块**去编辑，也没有强制的失败归因流程——选择突变方向本身就是提议的一部分（与论文1 Recuris 的"组件强制归因"形成鲜明对比）；
- 每个候选先经冒烟测试，再在 D_dev 上端到端评估。

更新规则刻意严格（公式 5）：F_{t+1} = H_{t,j*} 当且仅当 S(H_{t,j*}) > S(F_t)（严格大于），j* = argmax_j S(H_t,j)；否则 F_{t+1} = F_t。**留出集从不进入提议、选择、晋升、早停或回滚**；晋升使用开发集上的确定性点估计比较——严格提升并不构成泛化的统计保证。搜索前沿与代码谱系可以不同（提议者可复用或组合存档代码）。

### 4.3 搜索接口与约束

可变对象是可执行的上下文构造代码：候选可改变证据表示、检索、导航、选择、打包、辅助提示或其组合。**内层 VLM、回答接口、任务指标、评估器可用的数据在搜索协议内全部固定**。这一契约把"模型改进"与"harness 改进"分离，同时程序空间仍足够表达，可涵盖均匀访问、检索与多阶段导航。

### 4.4 实验设置要点

- **数据**：LVBench 公开元数据 103 视频/1,549 QA；因版权下架 20 个源视频，本地实收 83 视频/1,232 QA（整视频剔除而非随机抽题）。Random(42).shuffle 后 [0:350] 为搜索开发集、[350:] 共 882 题为最终留出集。跨基准：Video-MME（2,700 QA）与 MLVU（2,174 QA）全集，选出的 harness 在目标基准评估前冻结、无任何目标特定搜索。
- **冻结模型与协议**：Qwen3-VL-8B-Instruct，温度 0、关闭 thinking；每次 VLM 调用至多 K=40 个视觉观察；harness 代码可用 2-fps 视频流；语义图像检索用冻结的 CLIP ViT-B/32；跨所有受控比较共享"仅字母"回答接口。
- **搜索协议**：提议者为 Claude Opus 4.6（经 Claude Code），可查看当前前沿与存档工件。两条初始化轨迹各 10 次迭代：弱种子 UNIFORM-40 → 选出 STATEDTIMEADDRESSDECODE；强种子 AKS → 选出 CARDINALITYLEDGER。
- **受控参照构造器**：UNIFORM-40（答题时均匀选 K 帧）、CLIP-KNN（写 320 帧图像嵌入索引、问题直映图像近邻）、CAPTION-KNN（字幕近邻映射回帧）、AKS（自适应关键帧选择，平衡问题相关性与时间覆盖）；另有按文献模式移植的 WORLDMM-STYLE、HOMER-STYLE、VIDEOSEAL-MATCHED 结构对照，以及均匀采样下的专有 VLM 行（Gemini-2.5-Flash 33.7、GPT-5 46.5）。

| CLIP-KNN | 38.6 | 41.7 | 40.0 | 10,407 |
| CAPTION-KNN | 38.6 | 34.9 | 40.0 | 9,328 |
| AKS（手工父代） | 49.7 | 46.6 | 40.0 | 8,788 |
| WORLDMM-STYLE | — | 36.0 | 7.3 | ~4,200 |

两个互补结论：弱种子下递归搜索从 36.3 起点发现结构化程序（留出 +12.7）；强种子下同一过程把手工前沿从 46.6 推进到 54.8。检索式基线（CAPTION-KNN 留出 34.9 反而低于 dev 38.6）显示手工检索模式并不稳健；文献风格对照均低于 AKS。

**匹配累计视觉 token 对照（Table 2，关键公平性检验）**：CARDINALITYLEDGER 每次调用仍 ≤40 帧，但多阶段执行使累计视觉 token（19,210）接近 AKS-90（90 帧单调用，19,583）。AKS-90 把留出提到 49.2（434/882），证明"更多视觉上下文确有帮助"，但在相近累计成本下**仍落后 CARDINALITYLEDGER 5.6 个百分点**——收益来自上下文体量与"查询自适应的证据分配"（survey/refine/pack/ledger）两者。

**配对显著性（Table 9，20,000 次配对 bootstrap，seed 42）**：UNIFORM-40→STATEDTIMEADDRESSDECODE +12.7 [9.4, 16.0]；AKS→CARDINALITYLEDGER +8.2 [5.1, 11.2]；AKS-90→CARDINALITYLEDGER +5.6 [2.4, 8.7]；AKS-CL 配对不一致计数 63:135，精确双侧 McNemar p = 3.39×10⁻⁷。

**跨基准直接迁移（Table 3，零目标搜索）**：Video-MME（2,700 QA）：Uniform 59.9 / AKS 66.9 / CARDINALITYLEDGER 67.5；MLVU（2,174 QA）：Uniform 63.2 / AKS 72.0 / **CARDINALITYLEDGER 75.0**。在两个目标基准上均保持对强父代的优势，MLVU 上更大（+3.0），说明在 LVBench 上发现的程序结构可迁移出搜索所用开发分布。

## 六、消融与分析

1. **完整搜索轨迹（Table 5 / Fig 2-3）**：AKS 种子 10 候选中恰好 4 次严格前沿更新：AKS 49.7 → ZoomRefine 47.4（拒）→ StatedInterval 53.7（升）→ LegibleTimeline 52.6、OrdinalEnum 52.9（拒）→ SurveyCommit 55.7（升）→ PointerLadder 57.4（升）→ **CardinalityLedger 58.3（升）** → SectionedScan 58.0（拒）→ ContiguousAnchors 58.3（平手不晋升——严格大于规则的直接体现）→ SegmentTournament 54.9（拒）。四次更新依次引入：显式时间区间处理、基于 survey 的证据获取、指针式精化、基数感知记账。准确率-成本 Pareto 图同时呈现"严格递归改进"与"构造上下文的累计成本"。
2. **弱种子轨迹（Table 6）**：Uniform-40 36.0 → CaptionNavigateVerify 43.4（升）→ EmbedNavigate 48.6（升）→ 其后 6 个候选（TemporalDirectionRetrieve 45.7、ReasoningQueryBoost 46.6、MMRRelevanceDiverse 48.0、BurstRedecodeLocalize 42.6、DualChannelAnswer 42.0、MotionPairResolve 40.6）全部被拒 → STATEDTIMEADDRESSDECODE 50.9（升，留出 49.0）→ AttributedPackAnswer 48.6（拒）。共 3 次严格更新，展示搜索如何从最小构造器逐步建立"导航→嵌入检索→显式时间地址解码"的结构。
3. **搜索发现了什么程序（Fig 4）**：CARDINALITYLEDGER 是**查询自适应**执行而非固定帧选择器，执行深度按问题类型分流（350 题开发集统计）：显式时间区间问题 14.3%（50/350）单调用旁路指针搜索——24 帧区间突发 + 16 帧 AKS 全局锚点直接打包；短路双调用 1.7%；主导的指针阶梯路径 77.7%（272/350）：L0 全局 survey（27 张网格图/320 缩略图）给出粗指针时刻 → L1 精化 survey（同规格）→ 最终 40 帧打包（局部突发 + 全局 AKS 锚点）；计数类问题 6.3%（22/350）额外加 ledger 提取与纯文本对账（4 次调用）。轨迹示例：L0 指向 1:31/3:03/9:50，L1 精化到 14:44/15:08/15:36。作者强调 RSI 发现的是**查询条件化的执行结构**（何时旁路、何时缩放、何时加符号校验步骤），而不只是换一个帧打分函数。
4. **上下文构造的空间余量（Table 7 / Fig 5，oracle 分析）**：用标注证据区间的不可部署 oracle 对照均匀采样：K=40 差距 21.1 分（36.3 vs 57.4）、K=80 差 19.7、K=160 差 19.7、K=320 差 8.9（46.9 vs 55.7）——即使视觉预算大幅增加，上下文选择仍然重要，只是余量收窄。
5. **互补协议的负结果（Table 8）**：高容量字幕检索研究用另一 200/1,032 划分：字幕检索对均匀采样 dev +4.00（McNemar 9/17, p=.17），test 仅 +0.48（61/66, p=.72）——dev 上选出的 AdaptiveDensity-PRF 变体在测试上无改进。作者如实报告了这一"开发集信号不可迁移"的对照，佐证其协议的诚实性。
6. **可复现性审计（附录 F）**：发布工件固定 seed-42 划分、源可用性清单、逐题预测与正确性、两条轨迹的完整十步记录；对 AKS、STATEDTIMEADDRESSDECODE、CARDINALITYLEDGER 的开发集执行，上下文 sidecar 保存每次 VLM 调用的有序视觉输入、源帧索引/时间戳、图像哈希、请求文本与视觉 token 核算，支持重建与审计；但因外层提议依赖专有 LLM 服务，不保证可确定性地再生同一提议序列。

## 七、局限性与批判性评述

论文在 Scope and limitations 一节相当坦诚，以下合并评述：

1. **单模型、单种子、少量轨迹**：只用一个冻结 VLM（Qwen3-VL-8B）、一个数据 seed、每条轨迹仅 10 次迭代，无法得出跨模型行为或搜索方差层面的结论；"递归自改进"的证据强度受限于轨迹数量，且严格晋升规则下 4/10 的更新率意味着大量搜索算力被拒绝候选消耗。
2. **划分并非视频不相交**：LVBench 采用**问题级**而非视频级划分，开发与留出问题可能共享视频，跨"任务"迁移的解释力因此打折（这一点对"泛化"主张是实质性削弱）。
3. **提议者可能携带基准先验**：Claude Opus 4.6 的预训练数据可能包含 LVBench/Video-MME/MLVU 相关知识，搜索可能部分是"恢复已知设计"而非真正发现；论文承认但不能量化。
4. **成本核算不完整**：累计 token 只是输入侧上下文体量估计，未含离线索引、提议搜索、输出 token 与价格；AKS-90 对照只匹配视觉 token，文本侧与调用次数不同；多阶段 harness 的延迟成本未报告。
5. **每题独立构造上下文，无可变跨问题记忆**：与论文1的跨任务经验积累不同，本框架的程序对每个视频从头构造，"记忆"只存在于程序结构中，不积累实例级经验。
6. **收益的量级与统计口径**：MLVU/Video-MME 上的迁移优势（+3.0/+0.6）未给配对检验；Video-MME 上对 AKS 优势微弱（67.5 vs 66.9），跨基准结论中"ordering 一致"成立但幅度不均。
7. **点估计晋升规则的已知风险**：作者自己指出严格提升不是统计保证——开发集 350 题上 1 题约 0.29 分，前沿更新可能部分是开发集过拟合；留出与 oracle 分析缓解但不能消除该风险。
8. **RSI 语义的限定**：论文明确"递归自改进"仅指 harness 程序的迭代改进，不是 VLM 底层智能的递归放大——标题中的 RSI 应在此限定下理解。

## 八、对读者研究的启发

读者做多模态 Agent 长时程记忆 + RSI/harness 进化研究，本文是**多模态侧最直接的可对照基线**，启发与缺口如下：

1. **"可执行上下文构造"作为独立优化层的形式化可直接复用**：H(V,q;K) = Pack(Read(Write(V),q),K) 的三段分解同样适用于图像、文档、GUI 观测等多模态长输入；把"冻结模型 + 可变构造程序 + 有界每次调用预算"作为受控实验设计，是分离"harness 收益"与"模型收益"的干净范式，值得作为读者实验的基本盘。
2. **查询自适应执行深度是被搜索出的核心结构**：显式区间旁路 / L0→L1 指针精化 / 计数 ledger 的分工说明，进化出的价值不在帧打分而在**控制流**。读者做多模态长时程记忆时，可把"何时触发检索/何时缩放/何时做符号校验"显式作为可进化对象，而非只进化检索器参数。
3. **成本公平性协议值得照搬**：单次调用 K 固定 ≠ 累计计算固定；AKS-90 匹配累计视觉 token 对照是必要设计。任何 harness 进化工作都应同时报告准确率与累计上下文成本，否则多阶段程序可用"多花钱"伪装成"更聪明"。
4. **可审计工件包是差异化贡献**：完整谱系（代码、父代、假设、轨迹、逐题预测、上下文 sidecar、图像哈希）使 searched harness 可作为程序研究。读者若做 RSI 研究，建议从一开始就落盘这套审计结构——这也是与"只报最终分"工作的核心区别。
5. **与论文1（Recuris）的方法学对照构成研究光谱**：Recuris 强制组件级失败归因 + 验证门控 + 记忆跨任务积累；本文不指定突变方向、无显式失败归因、纯点估计前沿晋升、每题独立构造。两篇正好代表"结构化归因进化"与"自由程序搜索进化"两端；一个明确缺口是**两者结合**：在多模态 harness 搜索中加入结构化证据定位与回归门控，可能同时提高搜索效率与防过拟合能力。
6. **研究缺口**：(a) 视频不相交划分下的留出评估与跨模型/跨 VLM 规模迁移未做；(b) 跨问题可变记忆（把实例级经验写入程序外记忆）与本框架的程序搜索结合；(c) 提议者的基准先验污染量化（如在无公开基准的新数据上重复搜索）；(d) 文本侧 token、延迟与货币成本的完整核算；(e) 搜索方差（多种子多次轨迹）与更高效的搜索算法（当前 4/10 命中率）；(f) 将 paper1 式"checker 校验状态更新"引入视频证据获取（survey 指针的可验证性），打通"多模态长时程记忆 + 递归自改进"的完整闭环。
