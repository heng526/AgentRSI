# M3-Agent × Recuris：复现与 RSI 研究思路

日期：2026-09-28

## 一句话目标

先分别跑通 M3-Agent 的长视频记忆问答和 Recuris 的记忆策略进化，再研究：**跨问题的持久记忆纠错，能否减少后续错误；修复策略能否迁移到未见视频和另一套 Control 模型？**

## 当前进展

- node01 已部署 M3-Agent 官方 Control 33B 权重、Robot 子集 100 个视频的记忆图及 1,276 个 QA；双卡模型加载和 NCCL 通信通过。
- 无 API 的诊断运行已生成 10/10 个回答。该运行跳过了记忆检索和自动评分，只证明 Control 推理可运行。
- 完整检索还需查询向量服务；现有记忆图使用 `text-embedding-3-large`。Azure/OpenAI API 目前不可用，尚未得到论文可比的分数。

## 复现路线

1. **M3-Agent：**保留官方 Qwen3-32B Control，补齐与记忆图一致的检索向量服务，先跑 Robot，再跑 Web；固定模型、检索轮数、数据版本和评测协议。另接 GLM-5.3-Flash API 作为第二套 Control，在相同记忆与预算下比较。GLM-5.3-Flash 不能代替 embedding 模型；若使用智谱 `embedding-3`，须重算记忆图文本向量，并把结果标为改造配置。
2. **Recuris：**独立安装官方代码与基准，先比较裸 Agent、初始技能记忆 M0、作者发布的进化记忆；再运行至少一轮“失败轨迹 → 定位组件 → 局部补丁 → 验证门 → 接受/回滚”。GLM-5.3-Flash 用作固定 Meta-Agent，验证其接口和工具调用。优先选程序化评分的 SkillFlow；复现原论文数值需要匹配原模型及评测环境。
3. **两者结合：**把 M3 的视频事实图作为可持久修复的**事实记忆**，把 Recuris 的技能、工作状态、调用规则和校验规则作为可进化的**策略记忆**。先聚焦“人物身份关联错误 → 人物事实错误 → 后续问答错误”这一条链。修复时保留原始证据、标记受影响的派生事实，并让后续问题读取新记忆版本。

## 相关工作与创新风险：VideoHarness-RSI

[VideoHarness-RSI](https://github.com/Tencent/VideoHarness-RSI)已在冻结视频模型的条件下，用自动搜索改进视频证据的检索、选帧、组织和提示；其发布的有效方案主要改进**答题时的读取路径**。因此，“让 Meta-Agent 改检索提示或选帧策略”与已有工作重叠，不能作为我们的主要创新。Recuris 也已覆盖“工作记忆引导技能调用、失败定位、局部补丁与验证门”。

我们的研究边界应落在**持久事实记忆的跨问题纠错**：一次身份关联修复之后，追踪并复核依赖它的人物事实，让后续不同问题受益；再检验修复规则是否能迁移到未见视频。实验上需加入“只优化读取路径、不持久修复事实”的对照，以证明收益来自记忆纠错及其传播控制。

## 关键实验设计

按视频划分进化集、验证集、测试集，测试答案不进入修复过程。两套 Control（官方 Qwen、GLM）分别比较原始 M3、固定纠错规则、进化纠错策略，并加入 M0 检查 harness 本身的贡献。策略先在一套 Control 上进化，再原样迁移到另一套。主要看后续相关问题正确率、错误传播、误修复与回归、跨视频迁移和成本；所有条件使用相同证据与调用预算。

## 当前最重要的缺口

需要可用的 GLM API、独立 embedding 模型和稳定的答案评测。GLM 评分与原文 GPT-4o 评分不可直接对表。M3 官方 Control 当前按题读取预生成图，还没有跨问题提交修复的生命周期；这正是整合实现的核心。仅把工作记忆或自动改提示词接到 M3 上不足以说明 RSI，必须证明**修复进入下一轮、改变后续行为，并在未见任务上带来收益**。
